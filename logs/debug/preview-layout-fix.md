# PDF編集画面の見切れ・余白・幅合わせの点滅

- 種別: 問題対応
- 作成日: 2026-09-28
- エラー: あり（修正前のプレビュー再発防止テストが失敗）
- 対応状況: 解決確認済み（下記のブラウザ検証範囲）

## 要点

上部の操作とメニューの見切れ、空白に見える書き出しメニュー、画面下側の未使用領域、幅合わせ時の連続した点滅を修正しました。サムネイルの並び方とサイズは一覧のすぐ上に常時表示します。

## 目的・対象・前提

ブラウザの表示倍率100%のまま、ノートPCを含む異なる画面幅でPDFを編集できるようにする修正です。表示可能な幅・高さに合わせます。物理的なモニターのインチ数では判定しません。合意した要求は [仕様書](../../docs/spec.md) にあります。

## 起きていたことと原因

- 操作欄は1行に固定され、はみ出しを隠していました。実測では幅837pxの領域に1542px分の内容が並び、ページ数とメニューが見切れていました。
- 下に開くメニューも、その親である操作欄のはみ出し制限で切り落とされていました。書き出し横のボタンは、背景と継承された文字色が同色でした。
- アプリ全体には画面の高さが指定されていましたが、中間の編集領域には余った高さまで伸びる指定がありませんでした。高さ884pxの画面で、編集領域の下に286pxの未使用領域を確認しました。
- 幅合わせでは、倍率変更時に描画を消すと縦スクロールバーが消え、表示幅が15px増えていました。新しい幅で倍率を計算して描画するとスクロールバーが戻り、幅が減って再描画する繰り返しになっていました。最初の調査時は再現できず仮説でしたが、キーボードで「幅に合わせる」を選ぶと再現し、幅773pxと788px、倍率80.5%と82.1%の往復と描画の消失を観測しました。ユーザー報告の14.8%と100%という数値の組み合わせ自体は再現していません。

## 対応

上部の操作欄は文字を隠さずに折り返し、ページ数は専用の行にしました。「その他の操作」には新しく始める・分割線の全解除・終了を固定配置し、幅に応じて操作が移動する処理を取り除きました。

両メニューは同じ画面内配置処理を使います。上下の空きと画面端を考慮し、必要ならメニュー内をスクロールできます。文字色は配色の設定に従い、Escや外側クリックで閉じられます。

編集領域を縦方向に伸ばし、サムネイル操作部の高さも測って残りをプレビューと一覧に配分します。非常に低い画面では既存の最低高さを守り、編集領域全体を縦にスクロールできます。

点滅は、CSSの `scrollbar-gutter: stable` でスクロールバー用の幅を確保して解消しました。CSSは表示方法を指定する規則です。描画の有無で幅が変わらなくなるため、倍率の再計算が往復しません。この1点の変更で再発防止テストが失敗から成功へ変わることを先に確認し、PDFの描画処理そのものは変更していません。

## 確認方法

1. `web` ディレクトリで `npm run build` を実行します。アプリとブラウザテストのTypeScript型検査も含みます。
2. 同じディレクトリで `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 18766 --strictPort` を実行し、`http://127.0.0.1:18766/tests/preview-regression.html` を開きます。実際のプレビュー部品とCSSを使い、横長・縦長の幅合わせとページ全体表示について、描画完了後の倍率・空白・横のはみ出しを各40回確認します。スクロールバーが領域の幅を使う環境でも確認します。
3. リポジトリルートで `.\.venv\Scripts\python.exe web/tests/serve-ui-fixture.py` を実行し、出力されたローカルURLを開きます。生成した10ページのPDFと設定を `tmp/ui-smoke-*` 配下に分離し、実際の編集中セッションを使わずに表示方式の保存などを確認できます。
4. ウィンドウ幅・高さを変え、操作欄、ページ数、下端、メニューの表示範囲を測ります。並び方の変更、再読み込み後の設定維持、幅合わせ、ページ切り替え、Escと外側クリックを確認します。

## 確認結果

- ビルド・型検査は成功しました。PDF.jsを含む配布ファイルが500kBを超える旨の警告は残っています。
- 修正前のテストでは、横長PDFは40回中37回、縦長PDFは40回中38回、描画が消失しました。修正後は両方とも倍率変動0、空白0、横のはみ出し0で、ページ全体表示を含む3ケースが成功しました。
- 1366×768、1179×884、837×884、1024×650、768×540で横の見切れと下端の未使用領域がないことを確認しました。768×540では編集領域全体を縦にスクロールします。
- 実際のPDF描画でも、横長は82.5%、縦長は133.1%でそれぞれ安定し、連続30回の確認で描画消失0でした。ユーザーが開いていたPDFでも80.5%で安定し、描画消失0を確認しました。
- 横一列・横スクロールと複数列・縦スクロールを切り替え、複数列の設定が再読み込み後も保持されることを確認しました。
- 明るい配色と暗い配色でボタンの文字を確認し、両メニューが画面内に収まり、Escで閉じて見出しへフォーカスが戻り、外側クリックでも閉じることを確認しました。
- ブラウザ検証はCodex内蔵ブラウザで実施しました。単独のEdge・ChromeアプリやWindowsの表示倍率125%・150%での追加確認は未実施です。

## 再発時の確認順

1. 点滅時は、表示枠の幅とキャンバスの有無を交互に観測し、スクロールバーの出入りで幅が変わっていないか確認します。
2. 下側が空く場合は、外側から編集領域・作業領域・各ペインの高さを確認します。
3. メニューが切れる場合は、文字色、画面内の座標、親要素のはみ出し制限を確認します。
