## フェーズ2: 読み込みと編集状態

フェーズ1の API に載せる。編集状態の正本は Python バックエンドが持つ。ページの順番、削除、回転の正本は、画面が持たない。

### 実装

- [ ] `app/session.py` に編集状態と、Temp へのコピーを置く。起動時と終了時の残骸削除はフェーズ5で、同じモジュールに置く
- [ ] 追加単位に、識別子と元ファイル名を持たせる。パスは画面へ出さない。識別子はプロセス内で一意であればよい
- [ ] ページに、識別子、追加単位、元ページ番号（1 始まり）、現在の順、削除、回転を持たせる。この縦切りでは削除は常に偽、回転は 0 度である
- [ ] `POST /api/documents` で、multipart の PDF を 1 つ受け取る。成功で編集状態、失敗で理由を返す
- [ ] 処理中の別の `POST /api/documents` は 409 とする。進行中の読み込みも既存の編集状態も壊さない
- [ ] 読み込みに成功した PDF を、Windows Temp 配下のこのアプリ用ディレクトリへコピーし、以後そのコピーを使う
- [ ] 元の PDF は変更せず、ロックしない。元ファイルの内容は読み込み後も同じである
- [ ] PDF 以外、または pikepdf が開けないファイルは作業領域へ入れない。不完全なコピーは残さない
- [ ] パスワードが必要な PDF は、この縦切りでは入力を求めず、失敗として通知する
- [ ] 2 つ目の PDF を読み込んだときは、成功したときだけ作業領域をその PDF へ置き換える。置き換えに成功したときは、それまでのセッションコピーを消す
- [ ] 2 つ目の読み込みに失敗したときは、それまでの編集状態もセッションコピーも変えない
- [ ] 読み込み処理の開始から、成功の確定または失敗の確定まで、`POST /api/exports/all` は 409 とする
- [ ] `GET /api/session` で編集状態を返す。未読み込みなら空である
- [ ] `GET /api/session/file` でセッションコピーを返す。`Accept-Ranges: bytes`、圧縮無し。`Range` 要求には 206 で部分本体を返す
- [ ] `tests/test_session.py` を置く

## 対象範囲と対象外

対象は、Windows 上で次が通る縦切りである。

- 既定のブラウザに、Vite で組み立てた React（TypeScript）の画面を出す。ページの順番、削除、回転の正本は、この画面が持たない。
- PDF を 1 つ読み、ページを見て、見えている全ページを新しい PDF として書き出す。
- 元の PDF は変更せず、ロックしない。
- 編集状態の正本は Python バックエンドが持つ。

対象外:

- 回転、削除、並べ替え、分割線、選択ページの書き出し、分割書き出し、Undo / Redo
- 複数 PDF の同時読み込み、ドラッグ＆ドロップでの読み込み、開くパスワードの入力、電子署名 PDF の了承
- 選択 0 件、複数選択、ズームの 3 モード、サムネイルの列数とサイズの記憶
- 設定、ヘルプ、テーマ、未保存表示、自動終了、システムトレイ、exe 化、編集タブを 1 つに制限すること
- 前回保存先の記憶。保存ダイアログの初期フォルダは、毎回そのユーザーのドキュメントにする
- サムネイル解像度、ズーム上限、Undo 上限、大容量警告、ログ容量、更新確認先の数値確定

2 つ目の PDF を読み込んだときは、成功したときだけ作業領域をその PDF へ置き換える。置き換えに成功したときは、それまでのセッションコピーを消す。失敗したときは、それまでの編集状態もセッションコピーも変えない。読み込み処理の開始から、成功の確定または失敗の確定まで、`POST /api/exports/all` は 409 である。ダイアログ表示中または書き出し中に、進行中の読み込みを成功として確定しない。その読み込みは失敗とし、置き換え前の編集状態とセッションコピーを残す。

## 合意済みの受け入れ条件

- `python -m app` で 127.0.0.1 だけに待ち受け、既定ブラウザで画面を開く。他のホストにはバインドしない。
- 開発時は API ドキュメントを有効にし、開発時以外は無効にする。
- 画面の文言は日本語である。PDF を 1 つ選べる。読み込み後は 1 ページ目が大プレビューに出る。前後の移動でその 1 ページを表示する。
- サムネイルには、現在ページ番号、元 PDF 名、元ページ番号を出す。見えている範囲を描き、文書全体を先に画像化しない。
- 読み込みに成功した PDF は、Windows Temp 配下のこのアプリ用ディレクトリへコピーし、以後そのコピーを使う。元ファイルの内容は読み込み後も同じである。
- PDF 以外、または pikepdf が開けないファイルは作業領域へ入れない。不完全なコピーは残さない。パスワードが必要な PDF は、この縦切りでは入力を求めず、失敗として通知する。
- 各ページは、識別子、元 PDF の追加単位、元ページ番号、現在の順、削除状態、回転を持つ。この縦切りでは削除はせず、回転は 0 度である。

- 書き出し前に、宛先ドライブの空き容量がセッションコピーのサイズに満たなければ失敗し、ファイルを作らない。
- 最終ファイル名へ直接書かず、同じディレクトリの一時ファイルへ pikepdf でページをコピーする。PDF として開け、見えているページ数と一致することを確認してから確定する。失敗またはキャンセルでは一時ファイルを消し、編集状態は残す。
- 保存ダイアログの表示開始から、キャンセルで戻るまで、または書き出しジョブが終わるまで、新しい読み込みと別の書き出しは 409 で拒否する。`GET /api/session`、`GET /api/session/file`、進行中ジョブがあるときの `GET /api/exports/{job_id}` は、ダイアログ待ちのあいだも書き出し中も応答する。画面は段階、処理したページ数、全体に対する割合を表示する。残り時間は出さない。
- 成功後も編集状態は残る。実際に保存したファイル名と保存先、`PDF を開く`、`保存先を開く` を表示する。
- 起動時に、前回異常終了で残ったこのアプリ用の一時ディレクトリを消す。この縦切りの正常終了はプロセス終了フック（`atexit`）であり、そのときも消す。トレイの終了とアプリ内の終了は対象外である。
- API は、起動のたびに作る一時トークンを要求する。利用者はトークンを入力しない。トークンはプロセス終了で破棄する。トークンの無い API 要求は拒否する。

## 前提と制約

- アプリのソース、依存関係の設定、テストはリポジトリに無い。置くパスはリポジトリルート基準である。
- 開発機の Node.js は v24.15.0 である。
- 開発機では `python` が 3.11.9、`py` が 3.13.14 である。検証コマンドは `python` を使う。
- 自動テストはリポジトリルートで `python -m pytest`。ダイアログはテストで関数を差し替え、実ウィンドウを出さない。
- 依存の厳密な版は、Python は追加した `pyproject.toml`、画面は `web/package.json` を正とする。
- 選定した技術、保存ダイアログの担い手、一時トークン、編集状態の項目、この縦切りの API、画面は Vite、React、TypeScript であることが、仕様、アーキテクチャ、技術スタック、ADR 0002、ADR 0003 と一致している。
