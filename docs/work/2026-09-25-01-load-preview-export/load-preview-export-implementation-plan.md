## 対象範囲と対象外

対象は、Windows 上で次が通る縦切りである。

- 既定のブラウザに、Vite で組み立てた React（TypeScript）の画面を出す。ページの順番、削除、回転の正本は、この画面が持たない。
- PDF を 1 つ読み、ページを見て、見えている全ページを新しい PDF として書き出す。
- 元の PDF は変更せず、ロックしない。
- 編集状態の正本は Python バックエンドが持つ。

対象外:

- 回転、削除、並べ替え、分割線、選択ページの書き出し、分割書き出し、Undo / Redo
- 複数 PDF の同時読み込み、開くパスワードの入力、電子署名 PDF の了承
- 選択 0 件、複数選択、ズームの 3 モード、サムネイルの列数とサイズの記憶
- 設定、ヘルプ、テーマ、未保存表示、自動終了、システムトレイ、exe 化、編集タブを 1 つに制限すること
- 前回保存先の記憶。保存ダイアログの初期フォルダは、毎回そのユーザーのドキュメントにする
- サムネイル解像度、ズーム上限、Undo 上限、大容量警告、ログ容量、更新確認先の数値確定

2 つ目の PDF を読み込んだときは、成功したときだけ作業領域をその PDF へ置き換える。失敗したときは、それまでの作業領域を残す。

## 合意要件と受け入れ条件

用語は [CONTEXT.md](../../../CONTEXT.md) に従う。製品全体の要求は [仕様](../../spec.md) にあり、この計画はそのうち読み込み、表示、全ページ書き出しだけを実装する。

受け入れ条件:

- `python -m app` で 127.0.0.1 だけに待ち受け、既定ブラウザで画面を開く。他のホストにはバインドしない。
- 開発時は API ドキュメントを有効にし、開発時以外は無効にする。
- 画面の文言は日本語である。PDF を 1 つ選べる。読み込み後は 1 ページ目が大プレビューに出る。前後の移動でその 1 ページを表示する。
- サムネイルには、現在ページ番号、元 PDF 名、元ページ番号を出す。見えている範囲を描き、文書全体を先に画像化しない。
- 読み込みに成功した PDF は、Windows Temp 配下のこのアプリ用ディレクトリへコピーし、以後そのコピーを使う。元ファイルの内容は読み込み後も同じである。
- PDF 以外、または pikepdf が開けないファイルは作業領域へ入れない。不完全なコピーは残さない。パスワードが必要な PDF は、この縦切りでは入力を求めず、失敗として通知する。
- 各ページは、識別子、元 PDF の追加単位、元ページ番号、現在の順、削除状態、回転を持つ。この縦切りでは削除はせず、回転は 0 度である。
- 全ページの書き出しは、バックエンドが Windows の保存ダイアログを出す。初期フォルダはドキュメント、初期ファイル名は `元ファイル名_編集済み.pdf` である。利用者がダイアログで名前を変えたときは、その名前を使う。
- 同名ファイルは上書きしない。拡張子の前に `(1)`、`(2)` を付ける。
- 書き出し前に、宛先ドライブの空き容量がセッションコピーのサイズに満たなければ失敗し、ファイルを作らない。
- 最終ファイル名へ直接書かず、同じディレクトリの一時ファイルへ pikepdf でページをコピーする。PDF として開け、見えているページ数と一致することを確認してから確定する。失敗またはキャンセルでは一時ファイルを消し、編集状態は残す。
- 書き出し中は、新しい読み込みと別の書き出しを受け付けない。画面は段階、処理したページ数、全体に対する割合を表示する。残り時間は出さない。
- 成功後も編集状態は残る。実際に保存したファイル名と保存先、`PDF を開く`、`保存先を開く` を表示する。
- 起動時に、前回異常終了で残ったこのアプリ用の一時ディレクトリを消す。正常終了時も消す。
- API は、起動のたびに作る一時トークンを要求する。利用者はトークンを入力しない。トークンはプロセス終了で破棄する。トークンの無い API 要求は拒否する。

## 実装方針と変更箇所

アプリのソース、依存関係の設定、テストはリポジトリに無い。次を新規に置く。パスはリポジトリルート基準である。

- `pyproject.toml`: Python 3.11 以上。実行依存は FastAPI、uvicorn、pikepdf。検証依存は pytest と、FastAPI の TestClient が使う httpx。厳密な版は、追加したこのファイルを正とする
- `app/__main__.py`: `python -m app` で 127.0.0.1:8765 に uvicorn を起動し、待ち受け開始後に既定ブラウザを開く。ポートを取れなければメッセージを出して終了する
- `app/main.py`: FastAPI。開発時だけ `/docs` を有効にする。環境変数 `PDF_EDITOR_ENV` が未設定または `development` のときを開発時とする
- `app/auth.py`: 起動時にトークンを 1 つ作る。画面 HTML の meta 要素へ埋め、API は `Authorization: Bearer` を要求する
- `app/session.py`: 編集状態、Temp へのコピー、起動時の残骸削除
- `app/export.py`: ページコピー、一時ファイル、検証、衝突回避、空き容量
- `app/save_dialog.py`: ctypes で Windows の保存ダイアログとドキュメントフォルダ（Known Folder）を呼ぶ。tkinter は使わない
- `app/open_path.py`: 保存した PDF と、そのファイルを選択したエクスプローラを開く
- `web/package.json`、`web/package-lock.json`、`web/tsconfig.json`、`web/vite.config.ts`、`web/index.html`、`web/src/` の React コンポーネント。言語は TypeScript。依存は React、PDF.js の `pdfjs-dist`、組み立て用の Vite。厳密な版は `web/package.json` を正とする
- 画面の組み立ては開発時に `web` で行う。FastAPI は組み立てたファイルを配信する。実行中のアプリは Node.js を使わない。PDF.js は組み立て結果に含め、CDN からは読まない。起動のたびに変わるトークンは、組み立て時に埋め込まず、FastAPI が配信する HTML へ入れる
- `tests/test_auth.py`、`tests/test_session.py`、`tests/test_export.py`

編集状態は次の項目を持つ。識別子はプロセス内で一意であればよい。

- 追加単位: 識別子、元ファイル名（パスは画面へ出さない）
- ページ: 識別子、追加単位、元ページ番号（1 始まり）、現在の順、削除（この縦切りでは常に偽）、回転（この縦切りでは 0）

API:

- `GET /`: トークン入りの HTML
- `POST /api/documents`: multipart で PDF を 1 つ受け取る。成功で編集状態、失敗で理由。書き出し中は 409
- `GET /api/session`: 編集状態。未読み込みなら空
- `GET /api/session/file`: セッションコピー。`Accept-Ranges: bytes`、圧縮無し。PDF.js は `httpHeaders` にトークンを載せ、大きいファイルは Range で読む。先読みで全文を取らない（`disableStream` と `disableAutoFetch`）
- `POST /api/exports/all`: 保存ダイアログを出す。キャンセルならファイルを作らず戻る。選択後はジョブを始め、ジョブの識別子を返す
- `GET /api/exports/{job_id}`: 段階、処理ページ数、総ページ数、割合、完了または失敗、確定したパス
- `POST /api/exports/{job_id}/open-file` と `POST /api/exports/{job_id}/open-folder`: 成功後だけ有効

画面は、ファイル選択、サムネイル、大プレビュー、前後、書き出しボタン、進捗、保存結果だけを持つ。大プレビューは枠にページ全体が入る倍率 1 種類とする。サムネイルのキャンバスは、一覧の見えている位置だけ作る。React は Python から受け取った編集状態に合わせてこれらの表示を更新する。ページ記録の形は TypeScript で書く。開発機の Node.js は v24.15.0 である。

書き出しのダイアログは、HTTP 要求を処理するスレッドから ctypes で出す。ダイアログが返した名前が既存なら、上書き確認は出さず、拡張子の前に `(1)`、`(2)` を付けて空ける。一時ファイルは確定先と同じディレクトリに置き、検証後に置き換える。検証は pikepdf で開き、削除されていないページ数と一致することである。

開発機では `python` が 3.11.9、`py` が 3.13.14 である。検証コマンドは `python` を使う。

## 実装順序と依存関係

1. 骨格。待ち受け、トークン、静的ファイル、`python -m app`。他に依存しない。
2. 読み込みと編集状態。手順 1 の API に載せる。
3. 画面。手順 2 の編集状態とセッションコピーを、React と PDF.js で表示する。`web` で組み立て、FastAPI が配信する。
4. 書き出し。手順 2 の編集状態を pikepdf で書き出す。手順 3 とは独立に自動テストできる。画面の進捗と保存結果は手順 3 のあとに結ぶ。
5. 起動時と終了時の一時ディレクトリ削除。手順 2 と同じモジュールで確認する。

## 各段階の検証方法と完了条件

自動テストはリポジトリルートで `python -m pytest`。ダイアログはテストで関数を差し替え、実ウィンドウを出さない。

手順 1 の完了: トークン無しの API が拒否される。`PDF_EDITOR_ENV=production` で `/docs` が無い。バインド先の確認は、アプリの設定が 127.0.0.1 であることをテストで読む。

手順 2 の完了: テストで作った複数ページの PDF を読み、ページ数と元ページ番号が一致する。読み込み後も元ファイルの内容が同じである。PDF 以外と、パスワードが必要な PDF は作業領域に残らず、コピーも残らない。2 つ目の成功で置き換わり、2 つ目の失敗で前の状態が残る。

手順 3 の完了: `web` で `npm run build` が成功する。ブラウザで PDF を読み、1 ページ目が大プレビューに見え、次のページへ移れる。サムネイルに現在ページ番号と元ページ番号が見える。この確認は実装時にブラウザで行う。

手順 4 の完了: 差し替えたダイアログのパスへ書き出し、pikepdf で開いたページ数が一致し、元ファイルは変わらない。既存名は `(1)` へ避ける。キャンセルと検証失敗で一時ファイルが残らない。空き容量不足は、容量チェックを偽にしてファイルが無いことを確認する。進捗の取得で、完了時に処理ページ数と総ページ数が一致する。Windows で実ダイアログを 1 回開き、ドキュメントが初期フォルダであり、保存まで完了することを人手で確認する。

手順 5 の完了: アプリ用一時ディレクトリに残したファイルが、起動処理のあと無い。

全体の完了は、上記と `python -m pytest` の成功、および手順 3 のブラウザ確認である。
