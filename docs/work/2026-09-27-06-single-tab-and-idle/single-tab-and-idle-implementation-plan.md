## 対象範囲と対象外

対象範囲は、編集タブを 1 つにすること、再接続、対応外ブラウザの案内、自動終了、アプリ内の「終了」である。

- 編集権は 1 つのタブだけが持つ。2 つ目は案内を出し、編集できない
- F5 と、バックエンドが生きているあいだの再接続で、編集状態を戻す
- Edge と Chrome 以外では案内を出す。利用は禁止しない
- `idle_minutes` のあいだ操作が無いと警告し、続ける操作が無ければ終了する
- アプリ内の「終了」は、失われる状態があるときだけ確認し、一時データを消してバックエンドを止める

対象外は次のとおり。

- トレイの「開く」と「終了」、exe、単一インスタンス。アプリ内の終了が呼ぶ停止処理を、7 番目がトレイから使う
- 更新確認の通信
- 設定画面の中身、ヘルプ、テーマ
- 分割線、書き出し、新しく始めるの文言そのもの
- Windows のシャットダウンを遅らせること。スリープの特別扱い

## 合意要件と受け入れ条件

合意の出典は、[起動、編集タブ、終了](../../spec.md#起動編集タブ終了) と、[起動と終了の受け入れ条件](../../spec.md#要求ごとの受け入れ条件) である。

- 編集権はタブごとの識別子で持つ。識別子は、そのタブの再読み込みでは残り、別のタブには渡らない。F5 は同じ識別子で編集状態を読み直す
- 編集権を持つタブが開いているとき、別のタブの編集 API は 409 である。画面は「編集画面は別のタブで開いています。このタブでは編集できません。開いているタブに戻ってください。」だけを出す
- タブを閉じたら編集権を手放す。手放す時点は、保有中の識別子の応答が 5 秒途絶したあとである。画面は `pagehide` で release しない。F5 でも `pagehide` が発火し、即時に手放すと待機タブが編集権を取りうるためである。F5 は同じ識別子の再 claim だけで、5 秒以内なら編集権は移らない。途絶のあとは、待っていたタブが編集権を引き継ぎ、生きているバックエンドの編集状態を読む
- バックエンドが生きていれば、再接続と F5 でセッションを戻す。バックエンドに届かないときは、編集状態を作らない
- 起動時に前回の一時データが残っていたときは消し、「前回の終了が完了しなかったため、一時データを消去しました。」と出す。残っていなければ、この案内は出さない
- Microsoft Edge はユーザーエージェントの `Edg/`、Google Chrome は `Chrome/` があり `Edg/` と `OPR/` が無いものである。それ以外は「このブラウザは正式な対応対象ではありません。Microsoft Edge または Google Chrome を推奨します。このまま使うこともできます。」と出す。閉じるまでは残し、編集は止めない。閉じたことは次回起動へ持ち越さない
- 無操作の計測は `idle_minutes` である。クリック、キー、スクロール、設定の変更で最初からやり直す。マウスを動かしただけではやり直さない
- 残り 1 分で「操作が無いため、まもなく終了します。」と出す。未保存だけが真なら、その直後に「未保存の変更があります。」を足す。分割設定 未出力だけが真なら「まだ書き出していない分割設定があります。」を足す。両方なら「未保存の変更と、まだ書き出していない分割設定があります。」を足す。ボタンは「作業を続ける」である。押すと計測を最初からやり直す。警告を閉じただけでは計測は止まらない
- 書き出しが完了するか失敗するまで計測を進めない。タブを閉じたまま書き出している間も同じである
- 時間に達したら、一時データを消してバックエンドを止める。自動終了の直前に、新しく始めるとは別の確認は出さない
- アプリ内の「終了」は、未保存と分割設定 未出力が両方偽なら確認しない。どちらかが真なら、4 番目の計画の 1 つの確認を出す。実行後は一時データを消してバックエンドを止める。キャンセルは何も止めない
- Windows のシャットダウンと再起動は妨げない

## 現状

いまの `startup` は、一時ディレクトリがあれば毎回消す。クラッシュと初回起動を区別しない。編集権、無操作の計測、アプリ内の「終了」は無い。`python -m app` はポート 8765 を占有する。

## 実装方針

編集権はバックエンドが持つ。画面の識別子は `sessionStorage` に置き、リロードでは残り、新しいタブでは新しく作る。起動時トークンは全タブ共通なので、ヘッダ `X-Tab-Id` で保有タブと待機タブを分ける。

画面は `pagehide` でも F5 でも `POST /api/editor/release` を送らない。`navigator.sendBeacon` も使わない。編集権を手放すのは、保有中の識別子の応答が 5 秒途絶したあとである。

無操作の計測はバックエンドが、`startup` の直後から行う。編集権が無いあいだも進む。残り 60 秒を切った警告は、編集権を持つ画面が heartbeat の応答で出す。無操作のあいだにセッションを取り直す必要は無い。

テストは停止関数を差し替え、プロセスは殺さない。対応外ブラウザの案内は、編集権の有無と別に出す。既定ブラウザを開く処理は 7 番目が足す。

## 前提・制約・未決

- 着手は、4 番目の確認規則と、5 番目の `idle_minutes` がコードに入ってからである。この計画の作成時点では、どちらも未実装である。未実装でも、計画の前提はその API である。
- 同期状況: 仕様の起動、編集タブ、終了と受け入れ条件は、警告は 1 分前であること、編集権の引き継ぎ、前回の一時データを消した案内まで反映済みである。技術スタックに、この判断の置き場は無い。
- この計画のレビュー中は、同期セットの実ファイルは変えない。
