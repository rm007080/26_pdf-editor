## 概要

対象は、設定、ヘルプ、テーマ、Windows 通知、ツールバーが幅に収まらないときの格納、前回フォルダの記憶、自動終了までの時間の記憶である。

合意の出典は、[設定、ヘルプ、通知](../../spec.md#設定ヘルプ通知)、[書き出す](../../spec.md#書き出す)、[PDF を読み込む](../../spec.md#pdf-を読み込む)、[ADR 0004](../../adr/0004-view-preferences-in-backend-file.md) である。「PDF を選ぶ」を Windows のファイル選択にすることは、この計画で確定した。

設定のキーは、画面より先にテストで固定する。段階 1 と 2 の完了は、リポジトリルートの `python -m pytest` が成功することである。段階 3 の完了は、`web` の `npm run build` が成功し、ブラウザで確認することである。

- [x] `last_open_dir` と `last_save_dir` は、フォルダのパスまたは null として読む
- [x] `GET /api/settings` が、既存の 3 キーと新しいキーをすべて返すようにする
- [x] 通常の `PUT /api/settings` の必須キーを `thumbnail_layout`、`thumbnail_size`、`pane_ratio`、`theme`、`windows_notifications`、`idle_minutes` にする
- [x] この 6 キーが欠けるときは 400 とし、ファイルを変えない
- [x] `theme` が null、`light`、`dark` 以外のときは 400 とし、ファイルを変えない
- [x] `idle_minutes` が 30、60、120、240 以外のときは 400 とし、ファイルを変えない

## フェーズ2: フォルダ、通知、ログ

フォルダを書くのはサーバだけである。ダイアログで 1 件以上選んだときのフォルダを `last_open_dir` にする。受け取りの成否では変えない。ドラッグ＆ドロップはこのフォルダを更新しない。

### Windows のファイル選択

- [x] `POST /api/dialogs/open-pdfs` を、`ask_save_path` と同じ STA スレッドで開く
- [x] ダイアログは Windows の複数選択にし、フィルタは PDF、選んだ順を維持する
- [x] `try_begin(DIALOG)` が失敗したときは 409 とし、`finish` は呼ばない
- [x] 成功したあとは、ダイアログを開く前から受け取りが終わるまで活動を `DIALOG` にする
- [x] このあいだの `POST /api/documents` は、1 番目の計画どおり 409 にする
- [x] `Session.accept_upload` は、1 番目と 2 番目の計画どおり `try_begin(LOADING)` する。`open-pdfs` は `accept_upload` を呼ばない。`try_begin` は `IDLE` 以外を拒否するので、`DIALOG` 中に `accept_upload` を呼ぶと受け取りは失敗する
- [x] `open-pdfs` は `append_documents` を呼ばない。編集状態は変えない
- [x] 1 番目と 2 番目の受け取りから、活動の開始と終了を除いた本体を切り出す
- [x] 本体は `try_begin` も `finish` も呼ばない。`DIALOG` を保持したまま、バイト列と basename をその本体へ渡す
- [x] HTTP の `POST /api/documents` は、その本体の前後で従来どおり `try_begin(LOADING)` と `finish(LOADING)` を行う
- [x] `try_begin(DIALOG)` の成功後は、キャンセル、成功、例外のすべてで、応答を返す前に `finish(DIALOG)` する。`ExportService.begin_export` と同じである
- [x] 取りこぼしは、活動が `DIALOG` のときだけ `finish(DIALOG)` する
- [x] 例外のときは、その呼び出しで既に受け取った識別子を discard し、`last_open_dir` は変えない
- [x] 例外の応答は 500、詳細は「ファイル選択を完了できませんでした」とする。編集状態は変えない
- [x] キャンセルは `{ "status": "cancelled" }` とする。ファイルは受け取らない。`last_open_dir` は変えない。`DIALOG` を終えてから返す
- [x] 1 件以上選んだときの成功は `{ "status": "ok", "items": [ ... ] }` とする。`items` は選んだ順である
- [x] 選んだフォルダを `last_open_dir` にする
- [x] 開けた要素は、2 番目の計画の受け取り成功 JSON（`document_id`、`needs_password`、`byte_size`、`page_count`、`signed`、`duplicate`）に、basename だけの `filename` を足す。フルパスは出さない
- [x] 開けなかった要素は `{ "filename", "detail" }` だけとし、`document_id` は無く、コピーは残さない
- [x] 1 件の失敗で残りを打ち切らない。すべて処理し、`DIALOG` を終えてから返す
- [x] 取り込み時の `duplicate` は、2 番目の計画と同じ規則にする。作業領域にある追加単位か、その時点で了承済みの受け取りだけを見る
- [x] 同じダイアログで先にステージしただけで、まだ了承していない受け取りは、`duplicate` の判定に含めない
- [x] `last_open_dir` が null、またはその場所が使えないときは、ドキュメントを初期フォルダにし、「前回のフォルダが使えないため、ドキュメントを開きました。」と通知する
- [x] 使えない前回のフォルダからドキュメントへ切り替えたときだけ、`initial_folder_notice` に「前回のフォルダが使えないため、ドキュメントを開きました。」を付ける。キャンセルした応答にも付ける

### 重複の取り直し

- [x] `POST /api/documents/{document_id}/duplicate` を足す。本文は `{ "approved_document_ids" }`、応答は `{ "duplicate" }` だけである
- [x] サーバは、作業領域にある追加単位か、その配列の受け取りとハッシュが一致するときだけ `duplicate: true` を返す
- [x] まだ了承していないステージ済みは含めない。Undo で作業領域から外れた追加単位とは確認しない
- [x] 編集状態、コピー、活動は変えない。トークンを要求する
- [x] 未知の識別子と、パスワード未了の識別子は 400 にする

### 書き出しの初期フォルダ

書き出しの初期フォルダも同じ規則である。`last_save_dir` が null、またはその場所が使えないときは、ドキュメントを初期フォルダにし、「前回のフォルダが使えないため、ドキュメントを開きました。」と通知する。

- [x] 全ページ、選択ページ、分割の初期フォルダを `last_save_dir` にする
- [x] 使えない前回のフォルダからドキュメントへ切り替えたとき、`POST /api/exports/all`、`POST /api/exports/selection`、`POST /api/exports/split` の応答に、同じ `initial_folder_notice` を付ける
- [x] キャンセルと、分割の `{ "status": "naming" }` にも `initial_folder_notice` を付ける
- [x] 全ページと選択ページは、ジョブを始めたときのファイルの親フォルダを `last_save_dir` にする
- [x] 分割は、名前を確定してジョブを始めたとき、そのダイアログで選んだフォルダそのものを `last_save_dir` にする
- [x] サーバは、分割で選んだフォルダを、名前の確定まで覚えておく
- [x] ダイアログのキャンセル、および `POST /api/exports/split/cancel` では `last_save_dir` を更新しない

### Windows 通知

- [x] `app/notify.py` の `show_notification(title, body)` が、Windows のトーストを出すようにする
- [x] 呼び出すのは `ExportService` が、ジョブを完了または失敗に確定したときだけにする。画面の進捗取得では出さない
- [x] `windows_notifications` がオフのときは何もしない
- [x] タイトルは「PDF編集」とする。完了の本文は「書き出しが完了しました」、失敗の本文は「書き出しに失敗しました」とする
- [x] 本文にファイル名、パス、パスワードを出さない。ダイアログのキャンセルは失敗の通知にしない
- [x] このプロセスの中から出す。別プロセスや外部への通信はしない。通信をするライブラリは使わない
- [x] パッケージを足す場合は、`pyproject.toml` に版を固定し、同じ変更で [技術スタック](../../tech-stack.md) に用途と理由を 1 行足す
- [x] テストは `show_notification` を差し替える
- [x] 画面内の成功表示とエラー表示は残す

### 技術ログ、バージョン、HTML

この計画は、技術ログへの追記の呼び出しを足さない。完成版のログに、PDF 本文、パスワード、ファイル名、フルパス、共有サーバー名を含めない。

- [x] ログを `app/log_store.py` に置く。保存先は `%LOCALAPPDATA%\pdf-editor\logs` である
- [x] 削除関数は、30 日より古いファイルを消し、合計が 10 × 1024 × 1024 バイトを超えていれば古いファイルから、両方の上限に収まるまで消す
- [x] `POST /api/logs/open` を足す。フォルダが無ければ作ってから、既存の `open_folder` で開く。トークンを要求する。編集状態は変えない
- [x] `pyproject.toml` の `version` を起動時に読む。読めなければ `0.1.0` とする
- [x] `GET /api/about` が `{ "name": "PDF編集", "version" }` を返すようにする。トークンを要求する
- [x] `GET /settings` と `GET /help` が、`GET /` と同じ HTML（`render_index`）を返すようにする。トークンの埋め込みも同じにする
- [x] `GET /settings` と `GET /help` は `/api/` ではないので、Bearer を要求しない

## フェーズ3: 画面

画面は `App.tsx` を機能ごとのファイルへ分けない。HTTP は `web/src/api.ts`、型は `web/src/types.ts` に置く。アイコンはインライン SVG とし、アイコン用のパッケージは足さない。「更新を確認」は `GET` も `POST` も呼ばない。

### 画面遷移

- [x] React Router は足さない。History API の `pushState` と `popstate` で、パス `/`、`/settings`、`/help` を切り替える
- [x] 直入と再読み込みでも同じ HTML が開き、画面はパスで設定またはヘルプを出す
- [x] 編集画面は取り外さず隠す。選択、倍率、スクロールは、その DOM に残る
- [x] 画面の設定保存は、必須の 6 キーだけを送る

### 設定

- [x] 上部に「PDF 編集」「設定」「ヘルプ」を置く
- [x] テーマ、Windows 通知のオン / オフ、自動終了までの時間、設定の初期化を置く
- [x] 自動終了までの時間の選択肢は 30、60、120、240 分とする。初期値は 120 分である
- [x] `theme` が null のあいだは、ブラウザの `prefers-color-scheme` に合わせる
- [x] 利用者が選んだあとだけ記憶し、その後は OS の色が変わっても追従しない
- [x] 「設定を初期状態に戻す」は確認のあと、`POST /api/settings/reset` を呼ぶ
- [x] 確認の文言は「設定を初期状態に戻しますか？」とする。ボタンは「初期状態に戻す」と「キャンセル」とする
- [x] Esc はキャンセルにする。Enter は初期化を実行しない
- [x] 初期化のあと、テーマは null に戻り、再び OS の色に合わせる。両フォルダも null に戻る
- [x] 通常の PUT ではフォルダを消さない
- [x] 設定の下部に、アプリ名、バージョン、「更新を確認」を置く
- [x] 「エラーログの保存先を開く」は `POST /api/logs/open` を呼ぶ
- [x] 余白は、画面の端 16px、隣り合う操作の間隔 8px とする
- [x] アイコンは 20px、押せる範囲は 1 辺 36px とする
- [x] 操作名と本文は 14px、補足は 12px とする

### PDF を選ぶ

- [x] 「PDF を選ぶ」を、バックエンドの Windows ファイル選択にする。1 番目の計画のボタンを、このファイル選択へ置き換える
- [x] ドラッグ＆ドロップはブラウザのファイルのまま残す。読み込みフォルダは変えない
- [x] 画面は、選んだ PDF を `POST /api/documents` で再送しない
- [x] `DIALOG` が終わったあと、開けた `items` を選んだ順に 1 件ずつ確認する。1 件の確認が終わるまで次へ進まない
- [x] 確認の `{ファイル名}` は、その `filename` にする
- [x] 重複を出す直前の `duplicate` は、取り込み時の値をそのまま使わない。`POST /api/documents/{document_id}/duplicate` で取り直す
- [x] `approved_document_ids` は、同じ追加操作で画面が了承し、まだ discard していない識別子にする。キャンセルした識別子は配列に入れない
- [x] パスワードが必要な PDF は、正しいパスワードの成功応答のあと、電子署名や大容量より前に、この取り直しを行う
- [x] ドロップで同じファイルを順に送ったときの確認の有無と、この取り直しの真偽を揃える
- [x] キャンセルした識別子は discard し、了承した識別子だけを選んだ順で 1 回の `append_documents` に載せる
- [x] 開けなかった `filename` と `detail` は、閉じるまで残す通知にする。キャンセルした確認は、その通知に入れない
- [x] `initial_folder_notice` も、閉じるまで残す
- [x] ファイル選択のキャンセルは、編集状態を変えない

### ツールバーの格納

- [x] 幅の判定は `ResizeObserver` にする

- [x] それでも収まらなければ、終了、新しく始める、サムネイルの並びとサイズ、すべての分割線を解除、やり直す、元に戻す、左回転、右回転、削除の順で「...」へしまう

- [x] ページ番号の指定はしまう順に無いので、バーに残す
- [x] ボタンが画面に無い項目は飛ばす。格納の優先順には「終了」を含めるが、ボタンが無いあいだは飛ばす

## 前提、制約、対象外

前提は [末尾追加と未保存](../2026-09-27-01-append-documents-unsaved/append-documents-unsaved-implementation-plan.md) のドラッグ＆ドロップ、[読み込み前の確認](../2026-09-27-02-intake-checks/intake-checks-implementation-plan.md) の受け取り結果、[分割線と書き出し](../2026-09-27-03-split-lines-export/split-lines-export-implementation-plan.md) の書き出しダイアログ、[新しく始める](../2026-09-27-04-start-fresh-confirm/start-fresh-confirm-implementation-plan.md) の「新しく始める」である。未実装でも、計画の前提はその API である。

着手は、1 番目のドラッグ＆ドロップ、2 番目の受け取り結果、3 番目の書き出しダイアログ、4 番目の「新しく始める」がコードに入ってからである。受け取り JSON は、2 番目の計画が完了したあとの形を正とする。この計画の作成時点では、いずれも未実装である。前の単位の計画ファイルは書き換えない。

1 番目の計画は、ブラウザのファイル入力を複数選択にする。この計画は、そのボタンを Windows のファイル選択へ置き換える。ドラッグ＆ドロップは 1 番目の計画のままである。2 番目の計画の確認文言はファイル名を使う。3 番目の計画は、初期フォルダをドキュメントのままにしている。この計画が、そこへ前回の保存先を足す。6 番目以降は別計画である。

`idle_minutes` は 30、60、120、240 のいずれかで、初期値は 120 である。`windows_notifications` の初期値は true である。この計画は値を保存するだけで、タイマーは進めない。自動終了の動作は 6 番目である。この計画の `idle_minutes` を、その単位が読む。

開発版の API ドキュメントは、いまどおり `PDF_EDITOR_ENV=development` のときだけ有効である。この計画はそこを変えない。

対象範囲は、設定、ヘルプ、テーマ、Windows 通知、ツールバーが幅に収まらないときの格納、前回フォルダの記憶、自動終了までの時間の記憶である。その内訳は次のとおり。

- 「PDF 編集」「設定」「ヘルプ」と、ブラウザの戻る / 進む
- テーマ、Windows 通知のオン / オフ、自動終了までの時間、設定の初期化
- 「PDF を選ぶ」を、バックエンドの Windows ファイル選択にする。初期フォルダは前回の読み込みフォルダである。ドラッグ＆ドロップは残す
- 保存ダイアログと分割のフォルダ選択の初期フォルダを、前回の保存先にする
- 書き出しの完了と失敗を、設定がオンのとき Windows 通知にする
- ツールバーの文字を先に隠し、それでも収まらなければ指定順に「...」へしまう
- ヘルプに、基本操作、複数選択、分割、ショートカットを書く
- 技術ログの保存先を開き、30 日と 10MB の上限で古いものから消す
- 設定の下部に、アプリ名、バージョン、「更新を確認」を置く

対象外は次のとおり。

- 自動終了のタイマー、終了前の警告、「作業を続ける」。この計画は、選んだ時間を設定ファイルへ保存するだけである
- 編集タブを 1 つにすること、再接続、対応外ブラウザの案内
- アプリ内の終了とトレイがプロセスを止めること。格納の優先順には「終了」を含めるが、ボタンが無いあいだは飛ばす
- 更新確認の通信。ボタンは置く。通信先が決まるまでは要求を出さない
- 分割線、書き出しの中身、新しく始めるの確認文言
- トレイ、exe
- 技術ログへの追記そのもの。この計画は、フォルダ、上限での削除、保存先を開くところまでである

## 未決事項

この計画を止めない未決は、[仕様の未決](../../spec.md#unresolved) の更新確認先である。ボタンは置くが、通信はしない。6 番目以降の単位の内側の境界は、この計画では決めない。
