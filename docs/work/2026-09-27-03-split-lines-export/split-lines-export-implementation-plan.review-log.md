# 分割線と書き出し 計画レビュー記録

## 第1回（計画 v1 → v2）

- P0: 1 / P1: 4 / P2: 3
- 計画版: v2
- 担当: サブエージェント計画レビュー（generalPurpose / inherit）

### 指摘と対応

| 重大度 | 指摘 | 対応 |
| --- | --- | --- |
| P0 | 名前確定が `DIALOG` を跨リクエストで維持するのに、取り消し導線と早期 return の `finish(DIALOG)` が無く、F5 や通信失敗で編集が 409 のまま残る | ✅ v2。名前入力は取り消し以外で閉じない。`begin_export` と同じ早期 `finish`。マウント時と、名前入力を出せないときの `cancel`。フォルダ選択中の `cancel` は結果を捨てる。段階2・段階3・ブラウザ確認に追加 |
| P1 | `remove_documents` の逆コマンドが位置を持つ、という記述が前提の Undo 形（`original=append_documents` / `inverse=remove_documents`）と噛み合わず、Redo で詰めた線を戻す手順が無い | ✅ v2。削除は `restore_deleted` が直前の位置を戻す。末尾追加は Undo 記録へ `remove_documents` 適用直前の位置を書き、Redo の `append_documents` のあと書き戻す。段階1に並べ替え後の Undo / Redo を追加 |
| P1 | 検証後の architecture 縦切り文（画面が送るコマンド、分割未導入、`reset` 無し）の置換タスクが無い | ✅ v2。検証後の置換文と、構成要素の導入済み一覧を同期状況へ書いた。実ファイルはこの計画の検証前は変えない |
| P1 | 分割成功後に画面が `split_unexported` を取り直す手順が無い | ✅ v2。`completed` のあと `GET /api/session`。ジョブ応答にはフラグを含めない。ブラウザ確認へ紐づけ |
| P1 | 選んだフォルダの保持場所と、cancel / 成功 / 失敗での破棄が未記載 | ✅ v2。`ExportService` のメモリだけにディレクトリ、提案名、ページ識別子を持つ。cancel、400、`EXPORTING` 遷移、プロセス終了の破棄を書いた |
| P2 | 段階3「線を入れたときだけ出て」が、成功後の再表示と矛盾しうる | ✅ v2。未出力のときだけ出て、成功で消え、まとまりが変われば再び出る、に直した |
| P2 | `remove_documents` 後の位置詰めのテストが段階1に無い | ✅ v2。P1 の Undo / Redo 受け入れに含めた |
| P2 | `_user_command_error` が `page_ids` を要求する分岐が計画に弱い | ✅ v2。`_user_command_error` / `_normalize` / `_inverse` / `_mutate` の更新を変更箇所に書いた |

## 第2回（計画 v2 → v3）

- P0: 1 / P1: 2 / P2: 1
- 計画版: v3
- 担当: サブエージェント計画レビュー（generalPurpose / inherit）

### 指摘と対応

| 重大度 | 指摘 | 対応 |
| --- | --- | --- |
| P0 | フォルダ選択の遅延復帰でも `finish(DIALOG)` でき、cancel 後に始まった全ページの `DIALOG` を落とせる | ✅ v3。`cancel` は分割の保留があるときだけ即 `finish`。遅延復帰は結果を捨てるだけで `finish` しない。段階2にフォルダ待ち cancel のあと全ページの `DIALOG` が残る受け入れを追加 |
| P1 | 反映済みをページ識別子の列とすると、同一まとまり内の並べ替えでも `split_unexported` が真になりうる | ✅ v3。比較はまとまりごとの所属で、まとまりの中の順は見ない。段階2に同一まとまり内の並べ替えを追加 |
| P1 | Undo 記録へ `split_positions` を足す拡張が、architecture と ADR 0007 の置換タスクに無い | ✅ v3。検証後の置換文を同期状況へ追加。実ファイルはこの反復では変えない |
| P2 | 名前待ちが無い `confirm` の応答が未記載 | ✅ v3。409 とし、活動も編集状態も変えない |
