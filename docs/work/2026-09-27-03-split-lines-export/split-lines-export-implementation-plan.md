## フェーズ1: 分割線

画面の分割線は、このフェーズのコマンドがテストで固定されてから置く。

### セッションの位置番号

- [x] 分割線の正本をセッションの位置番号にする
- [x] `split_positions` を、見えている並びで線の直前にあるページの、1 始まりの現在ページ番号を昇順に並べた配列にする
- [x] 空配列は線が無いこととする
- [x] セッション応答に `split_positions` と `split_unexported` を足す
- [x] `GET /api/session`、選択の PATCH、コマンドの成功応答に含める
- [x] 選択の PATCH は `split_positions` も `split_unexported` も変えない
- [x] サーバの分割線は、見えている並びの位置番号とする
- [x] 空のまとまりになる線と、末尾の後ろの線は取り除く
- [x] 同じ位置に重なった線は 1 本にする

### コマンド

- [x] `app/session.py` の `CLIENT_COMMANDS` に `set_split`、`clear_split`、`clear_all_splits` を足す
- [x] `set_split` のクライアント本文は `after_page_id` だけにする
- [x] `set_split` と `clear_split` は、見えている並びで `after_page_id` のページの直後を境目にする
- [x] `after_page_ids` は、`clear_all_splits` の逆コマンドだけが持つようにする
- [x] `_user_command_error` で、分割の 3 種は `page_ids` を要求しない
- [x] `set_split` と `clear_split` は `after_page_id` だけを検証する
- [x] 末尾のページ、見えていないページ、未知のページは 400 とし、編集状態を変えない
- [x] すでにその境目がある `set_split` と、無い境目の `clear_split` は履歴に入れない
- [x] `clear_all_splits` は識別子を持たない
- [x] `clear_all_splits` は識別子の無い本文だけを受け、`after_page_ids` や `page_ids` があれば 400 にする
- [x] クライアントの `set_split` に `page_ids` または `after_page_ids` があれば 400 にする
- [x] 分割線が 0 本のときの `clear_all_splits` は履歴に入れない
- [x] `_normalize`、`_inverse`、`_mutate` で、この 3 種と履歴の中だけの複数本 `set_split` を扱う
- [x] `_operation_phrase` は、`set_split` を「分割線を入れる」、複数本の `set_split` を「解除した分割線を戻す」、`clear_split` を「分割線を外す」、`clear_all_splits` を「すべての分割線を解除する」とする
- [x] `clear_all_splits` の Undo は、解除した直前ページの識別子を並べた 1 件の `set_split` にする
- [x] この複数本は履歴の中だけにあり、クライアントが同じ形を送ると 400 にする

### 削除、並べ替え、末尾追加での位置

- [x] 削除と `remove_documents` は、外れるページより後ろの位置番号を詰め、空になる線と末尾の後ろの線を除き、同じ位置は 1 本にする
- [x] 並べ替えと末尾追加の適用そのものは、既存の位置番号を動かさない
- [x] 追加したページは最後のまとまりに入る
- [x] 削除の逆コマンド `restore_deleted` に、削除を適用する直前の `split_positions` を持たせる
- [x] ページを戻したあと、その位置番号を書き戻す
- [x] Redo の `delete` は、再び詰めと空線除去をする
- [x] 並べ替えの逆コマンド `restore_order` は位置番号を持たない
- [x] 末尾追加の Undo 記録は、1 番目の計画どおり `original` が `append_documents`、`inverse` が `remove_documents` のままにする
- [x] 位置番号は、`remove_documents` の本文には入れない
- [x] Undo で `remove_documents` を適用する直前の `split_positions` を、その Undo 記録へ書く
- [x] Redo では、`append_documents` でページを戻したあと、記録へ書いたその直前の位置番号を書き戻す
- [x] クライアントが `remove_documents` を送ると 400 のままにする

### 受け入れ

- [x] `set_split` と `clear_split` が 1 本を変える
- [x] 同じ状態の再送は `changed: false` である
- [x] 末尾のページは 400 で、線も履歴も変えない
- [x] 未知のページは 400 で、線も履歴も変えない
- [x] 見えていないページは 400 で、線も履歴も変えない
- [x] `1 2 | 3 4` からページ 2 を削除すると `1 | 3 4` になる
- [x] `1 2 | 3 4` からページ 3 を先頭へ移すと `3 1 | 2 4` になる
- [x] 空になる線が消える
- [x] Undo で削除前の線の位置が戻る
- [x] `clear_all_splits` が 1 件の Undo で、複数本の `set_split` として戻る
- [x] クライアントの `after_page_ids` は 400 である
- [x] `1 2 | 3 4` へ末尾追加し、追加ページを先頭へ並べ替える
- [x] その並べ替えを Undo してから追加を Undo すると、追加ページが外れ、線は追加直前の位置に戻る
- [x] 追加を Redo すると、ページは末尾に戻り、`remove_documents` 適用直前の線の位置が戻る
- [x] 続けて並べ替えを Redo しても、線の位置番号は動かない

### 分割の 3 口

- [x] 人の入力を待っているあいだは `DIALOG` のままにし、編集コマンドは 409 にする
- [x] 分割の保留は、フォルダ待ちと名前待ちのどちらか 1 つだけを `ExportService` が持つようにする
- [x] `POST /api/exports/split` は、`ExportService.begin_export` と同じく、`try_begin(DIALOG)` のあと、自分の早期 return でだけ `finish(DIALOG)` する
- [x] 見えているページが 0 枚、フォルダ選択の例外、ダイアログで選ばずに閉じたときを、その早期 return にする
- [x] `try_begin` に失敗したときは、まだ始めていないので `finish` しない
- [x] API の `cancel` がすでにその保留を終えているときは、フォルダ選択が戻っても結果を捨てるだけで、`finish` しない
- [x] `POST /api/exports/split` はフォルダ選択を開く
- [x] 選ばずに閉じたときは `{ "status": "cancelled" }` で、そのリクエストが `DIALOG` を終える
- [x] 選んだときは `{ "status": "naming", "files": [{ "name", "pages" }] }` を返し、`DIALOG` を維持する
- [x] `files` は提案名と、そのまとまりのページ数にする
- [x] ディレクトリのフルパスは応答に入れない
- [x] `POST /api/exports/split/confirm` の本文は `names` だけにする
- [x] 件数は提案と一致し、各名前は `.pdf` で終わるようにする
- [x] 空、`<>:"/\|?*` を含む、末尾が空白またはピリオド、同じジョブ内の重複は 400 とし、書き出さず、`DIALOG` を維持する
- [x] 名前待ちが無い `confirm` は 409 とし、活動も編集状態も変えない
- [x] 成功時は `{ "job_id" }` で書き出しへ移る

- [x] フォルダ選択が後から戻っても、結果は捨てるだけで、そこでは `finish` しない
- [x] 全ページと選択ページの保存ダイアログは、分割の保留が無いので触らない
- [x] ジョブ開始後の中止口は作らない
- [x] 保留が無いとき、および `LOADING` と `EXPORTING` のときは、活動も編集状態も変えず成功する
- [x] キャンセルと、名前の確定前の取り消しは、編集状態を変えない

## 対象範囲と対象外

対象範囲は、見えている並びの分割線と、選択ページおよび分割の書き出しと、「分割設定 未出力」である。

- 隣り合うサムネイルのあいだのクリックで、分割線を入れる、または外す
- 「すべての分割線を解除」を 1 操作にする
- 削除では線の後ろのページを後ろのまとまりに残し、並べ替えでは線の位置番号を動かさない
- 選択ページを、見えている並びの順で 1 つの PDF にする
- 分割線で分かれたまとまりごとに PDF にする。フォルダは 1 回、各ファイル名は個別に変える
- 「分割設定 未出力」を、必要なときだけ出し、クリックで分割の書き出しへ進む

対象外は次のとおり。

- 末尾追加、ドラッグ＆ドロップ、未保存の基準そのもの。この計画は `unsaved` を消さない
- パスワード、電子署名、大容量、重複の確認と、同一内容の一時コピー共有
- 「新しく始める」と、終了時に失われる状態をまとめた確認
- 設定、ヘルプ、テーマ、Windows 通知、ツールバーを「...」へしまうこと。しまい込みは 5 番目の計画である
- 前回の保存先フォルダの記憶と、使えない前回の場所からドキュメントへ切り替えたときの通知。初期フォルダは、いまの全ページ書き出しと同じくドキュメントである。前回の保存先の記憶は、5 番目の設定に残す
- 編集タブを 1 つにすること、再接続、ブラウザの案内、自動終了
- トレイ、exe、更新確認の通信先
- 書き出し PDF への新しいパスワード

## 前提、制約、同期状況

着手は、1 番目の末尾追加と未保存、2 番目の確認と復号したセッションコピーがコードに入ってからである。この計画の作成時点では、どちらも未実装である。

1 番目の計画は、コピー元を追加単位ごとのセッションコピーへ変える。この計画の選択ページと分割は、そのコピーを使う。1 番目と 2 番目の計画ファイルは書き換えない。

`GET /api/session` は、1 番目の計画どおり書き出し中も応答する。

いまのコードでは、`CLIENT_COMMANDS` は `rotate`、`delete`、`reorder`、`undo`、`redo` だけである。分割線のフィールドはセッションに無い。`_user_command_error` は、いま先頭で `page_ids` を要求する。`ExportService._copy_pages` は `session_file_path()` の 1 ファイルだけをコピーし、`_plan` は見えている全ページと `documents[0]` のファイル名を使う。保存は `ask_save_path` の 1 ファイルだけである。フォルダ選択は無い。画面の書き出しは「全ページを書き出す」だけである。

技術スタックに、この判断の置き場は無い。実装状況と、編集状態にある縦切りの現状文は、この計画の検証前なので変えない。

同期状況: 同期済み。仕様の書き出しへ、分割線が無いときの `名前_1.pdf`、見えているページが 0 枚のときは 3 種類とも実行できないこと、複数 PDF の開き方を反映した。未保存と分割設定へ、`分割設定 未出力` の出る条件と、クリック先を反映した。アーキテクチャの編集状態へ、`split_positions`、`split_unexported`、選択ページと分割の API、削除時の位置の詰めを反映した。このレビューの反復では、ADR の実ファイルは変えない。
