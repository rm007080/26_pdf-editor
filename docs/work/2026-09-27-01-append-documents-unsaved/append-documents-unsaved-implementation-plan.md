## 対象範囲と対象外

対象範囲は、開けた PDF を作業領域の末尾へ追加し、未保存を仕様の基準で出すことである。

- ファイル選択とドラッグ＆ドロップで、複数の PDF を選んだ順またはドロップした順に、1つの作業領域へ追加する
- 受け取りは編集状態を変えず、作業領域へ入れるのは `append_documents` である
- 1回の操作で実際に入った追加単位を、Undo の1件にする
- 未保存の基準と、「未保存」の表示、そのクリックから全ページの書き出しへ進むこと
- 全ページの書き出しが、追加単位ごとのセッションコピーからページをコピーし、複数の追加単位があるときの初期ファイル名規則に合うこと

対象外は次のとおり。

- パスワード入力、電子署名の了承、大容量の確認、重複の確認。開けない PDF と、パスワードが必要な PDF は、いまと同じくそのファイルだけを失敗にする
- 同一内容の一時コピーの共有。アーキテクチャの製品目標としては残し、重複確認の単位で実装する。この計画は追加のたびにコピーを作る
- 分割線、選択ページの書き出し、分割の書き出し、分割設定 未出力
- 「新しく始める」と、終了時に失われる状態をまとめた確認
- 設定、ヘルプ、テーマ、Windows 通知、ツールバーを「...」へしまうこと
- 編集タブを1つにすること、再接続、ブラウザの案内、自動終了
- トレイ、exe、更新確認の通信先
- pikepdf で開いてページ数を確定する以外の、ページ単体の破損検査
- 確認ダイアログの個別キャンセル

## 合意要件と受け入れ条件

合意の出典は、[PDF を読み込む](../../spec.md#pdf-を読み込む)、[書き出す](../../spec.md#書き出す)、[元に戻す](../../spec.md#元に戻す) の直後にある「未保存と分割設定」、[編集状態](../../spec.md#編集状態) である。

- 空の作業領域への読み込みも、編集途中の末尾追加も `append_documents` である。本文は `document_ids` だけで、バイト列とパスは含まない
- `POST /api/documents` は PDF を1つ受け取り、追加単位の識別子だけを返す。編集状態も履歴も変えない。成功した応答で作業領域を置き換えない
- キャンセルした追加は `append_documents` を送らない。受け取ったコピーは消し、編集状態は残す
- 読み込み中は新しい追加を始められない。失敗したファイルだけを除き、開けたファイルは1回の履歴で末尾へ入る。失敗したファイルはファイル名と理由を残す。すべて成功したときは短い成功通知にする
- 追加単位が無い作業領域への追加が終わったあとは、見えている1ページ目を選択し、それをアクティブページにする。すでに追加単位があるときの追加は、選択とアクティブページと、倍率、表示モード、ページ内の位置を維持する
- 逆コマンド `remove_documents` は同じ `document_ids` を持つ。ページの `delete` とは別である。クライアントが送ると 400 であり、Undo だけが適用する
- PDF を1件だけ、追加単位の無い作業領域へ入れたときは保存済み相当である。複数 PDF の初回読み込みと、編集途中の末尾追加は未保存である。Undo や Redo のあと、見えている出力が基準と一致すれば未保存は解ける。全ページの書き出しが正常に終わったときだけ基準を更新する。失敗とキャンセルでは更新しない。書き出したあとも履歴は残る
- 「未保存」は必要なときだけ出す。クリックは全ページの書き出しと同じ操作である。見えているページが 0 枚のときは、その書き出しと同じ理由で実行しない
- 全ページの初期ファイル名は、見えているページが残っている追加単位のうち、最初に追加したもののファイル名に `_編集済み.pdf` を付ける
- 元の PDF は変更しない。失敗時は、それまでの編集状態、選択、履歴、既に作業領域にあるセッションコピーを変えない

## 現状

いまのコードでは、`Session.accept_upload` が成功時に `documents` をその1件へ置き換え、履歴を空にし、`session_file` を1つにする。`POST /api/documents` はセッション全体を返す。画面の `postDocument` はその応答を編集状態として採用する。`openSessionPdf` は `GET /api/session/file` の1本だけを開く。`ExportService._copy_pages` はその1ファイルだけをコピー元にする。`App.tsx` のファイル入力は1件だけで、ドロップの受け口は無い。成功通知の短時間表示は `showToast`（4秒）が既にある。エラー表示は閉じるまで残る。

## 実装方針

書き出しまで PDF を1つにまとめない。追加単位ごとにセッションコピーを残し、画面は追加単位の識別子でそのコピーを開く。未保存の正本はセッションに置く。画面は `unsaved` を表示するだけで、基準を計算しない。

`app/session.py` の `CLIENT_COMMANDS` に `append_documents` を足す。`remove_documents` は足さない。画面は `App.tsx` を機能ごとのファイルへ分けない。HTTP は `web/src/api.ts`、PDF.js で開く処理は `web/src/pdf.ts` に置く。

画面の追加は、受け取りと `append_documents` がテストで固定されてから行う。書き出しの複数コピーは、追加単位ごとのファイル取得と同じ段階で固定する。
