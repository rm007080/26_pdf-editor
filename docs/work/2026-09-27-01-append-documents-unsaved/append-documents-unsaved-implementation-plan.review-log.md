# 末尾追加と未保存 計画レビュー記録

## 第1回（計画 v1 → v2）

- P0: 1 / P1: 2 / P2: 3
- 計画版: v2
- 担当: サブエージェント計画レビュー（generalPurpose / inherit）

### 指摘と対応

| 重大度 | 指摘 | 対応 |
| --- | --- | --- |
| P0 | `remove_documents` のあと Redo の `append_documents` がページ識別子・削除・回転をどう戻すか未定義。現状の採番だと選択と後続 Redo が壊れる | ✅ v2。外した追加単位のページ記録を残し、同じ `document_ids` の再適用は新規採番しない。段階1に Undo / Redo の受け入れを追加 |
| P1 | 検証後に古くなる architecture の縦切り現状文（画面が送るコマンド、置き換え、`session/file`、`unsaved` 未所持）の置換タスクが無い | ✅ v2。検証後の置換文を同期状況へ書いた。実ファイルはこの計画の検証前は変えない |
| P1 | 書き出し成功後に画面が `unsaved` を取り直す手順が無い | ✅ v2。`completed` のあと `GET /api/session`。ジョブ応答には `unsaved` を含めない。ブラウザ確認を追加 |
| P2 | Undo / Redo の操作文言が未定 | ✅ v2。「PDFを追加する」「追加したPDFを外す」 |
| P2 | discard の境界テストが段階1に無い | ✅ v2。作業領域と、Undo で残したページ記録を含む 400、空配列の成功を追加 |
| P2 | 1件追加の基準更新後に Undo で空になると `unsaved` が未定義 | ✅ v2。空でも基準と違えば真。複数追加の Undo で空に戻れば偽。0枚のクリックは書き出さない |

反映時の追加: discard は、Undo で外してページ記録が残る識別子を消さない。画面はセッションへ戻った追加単位のプロキシを開き直す。
