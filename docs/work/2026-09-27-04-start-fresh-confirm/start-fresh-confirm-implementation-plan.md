## 前提と制約

着手は、1 番目の `unsaved`、2 番目の作業領域外の受け取り、3 番目の `split_unexported` がコードに入ってからである。この計画の作成時点では、いずれも未実装である。

いまのコードでは、`startup` が一時ディレクトリを消してセッションを空にする。画面から作業領域だけを空に戻す口は無い。「新しく始める」のボタンも無い。`startup` は起動専用のまま残す。6番目の計画は、一時ディレクトリにファイルがある起動だけ `cleared_leftover` を `startup` に載せる。

確認は画面が持つ。サーバは、空に戻すことだけを行う。`unsaved` と `split_unexported` の正本は、これまでの計画どおりセッションである。

画面は `App.tsx` を機能ごとのファイルへ分けない。しまい込みは 5 番目の計画である。

完了日時は、フェーズ3の検証のあとだけ記録する。検証後の文書更新は、フェーズ4のチェックが終わってから記録する。この計画の作成時点では、アーキテクチャの現状文も実装状況も変えない。

検証後に [アーキテクチャ](../../architecture.md) を更新する。前の単位の計画ファイルは書き換えない。仕様の製品文と、編集状態にある `POST /api/session/reset` の製品 API の文は変えない。

アプリ内の終了、自動終了、トレイの終了は、この計画の失われる状態だけを確認の理由にする。プロセスを止める実装は、それぞれの単位である。

## 対象範囲と対象外

対象範囲は、「新しく始める」と、そのとき失われる状態の確認である。

- 未保存と分割設定 未出力が両方あるときは、1 つの確認にまとめる
- どちらか 1 つだけのときも確認する。失われるものが無いときは確認しない
- 確認のあと、作業領域、選択、履歴、分割線、一時コピーを空に戻す
- キャンセルは何も変えない

対象外は次のとおり。

- アプリ内の終了、自動終了、トレイの終了がバックエンドを止めること。失われる状態の種類は、この計画が固定した規則を後の単位が使う
- 設定の初期化の確認
- 分割線、選択ページと分割の書き出しそのもの
- パスワード、電子署名、大容量、重複の確認
- 設定、ヘルプ、テーマ、Windows 通知、ツールバーを「...」へしまうこと
- 編集タブを 1 つにすること、再接続、ブラウザの案内
- トレイ、exe、更新確認の通信先

## 合意要件と受け入れ条件

合意の出典は、[未保存と分割設定](../../spec.md#未保存と分割設定) と、[起動と終了の受け入れ条件](../../spec.md#要求ごとの受け入れ条件) である。

- 失われる状態は、未保存と分割設定 未出力だけである。履歴だけが残っていることは、確認の理由にしない
- 両方が偽のときは確認しない。1 つの PDF を読み込んだだけで未保存でなく、分割線も無いときは、確認せず作業領域を空にする
- 未保存だけの文言は「未保存の変更があります。破棄して新しく始めますか？」である。分割設定 未出力だけは「まだ書き出していない分割設定があります。破棄して新しく始めますか？」である。両方は「未保存の変更と、まだ書き出していない分割設定があります。破棄して新しく始めますか？」である
- ボタンは「破棄して新しく始める」と「キャンセル」である。Esc はキャンセルである。Enter は破棄を実行しない
- キャンセル、およびダイアログを閉じただけは、編集状態、履歴、一時コピーを変えない
- 実行後の作業領域は、追加単位もページも選択も履歴も分割線も無い。未保存と分割設定 未出力は偽である。作業領域の外に残っている受け取りも消す。一時コピーは、参照が残らないので消す
- 新しく始めるは Undo の対象にしない。実行後に元のページへは戻せない
- 読み込み中、ダイアログ中、書き出し中は 409 とし、状態を変えない。画面のボタンも、そのあいだは無効である
- 元の PDF は変更しない
