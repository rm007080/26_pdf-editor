## フェーズ1: コマンドと履歴

1 リクエストが、利用者が 1 回行った操作であり、状態が変わったときだけ Undo の 1 件になる。

### 実装

- [ ] `POST /api/session/commands` を追加する。トークンを要求する。成功時は更新後のセッションを返す。失敗時は編集状態も選択も履歴も変えない
- [ ] 読み込み中、ダイアログ中、書き出し中は 409 とする
- [ ] コマンドの `type` は `rotate`、`delete`、`reorder`、`undo`、`redo` である。未知の type は 400 とする
- [ ] `rotate` は `page_ids` と `direction`（`left` または `right`）を持つ。角度は 0 / 90 / 180 / 270 度で、右は +90、左は -90 である
- [ ] `delete` は `page_ids` を持つ。対象ページの `deleted` を真にする。見えている並びから外し、識別子は残す。元 PDF のページ実体は変えない
- [ ] `reorder` は `page_ids` と、`before_page_id` または `after_page_id` のどちらか一方を持つ。見えている並びで、指定したページの前または後へ、`page_ids` の現在順を保って動かす
- [ ] 履歴の 1 件は、逆コマンドと、操作前の `selected_page_ids` と `active_page_id` である。Redo の 1 件は、元のコマンドと、操作後の選択である。PDF のコピーは持たない
- [ ] 状態が変わらないコマンドは履歴に入れず、応答で変わらなかったことを返す
- [ ] Undo のあとで新しい編集をしたら、Redo を捨てる
- [ ] 上限は 100 件である。超えたときは古いものから捨て、最初の破棄のときだけ通知する
- [ ] セッションに、次の Undo と Redo が実行できるかと、ホバー用の短い文言を含める。実行できないときは、理由と次に起きないことを示す
- [ ] 作業領域の置き換え読み込みが成功したときは、履歴を空にする。失敗した置き換えでは、前の履歴も選択も残す
- [ ] `PATCH /api/session/selection` は履歴を増やさない
- [ ] 自動テストの境界は、この API とセッションの中身である。内部ファイルの分割は、この境界を守る範囲で実装が決める
- [ ] `tests/test_session.py` に、成功、400、409、履歴に入らない無変更、Undo 後の Redo 破棄、101 件目の破棄を足す

### 確認

- [ ] 回転の Undo が角度と選択を戻し、Redo が同じ回転と操作後の選択をやり直す
- [ ] 不正な `page_ids` は 400 であり、ページ、選択、履歴が直前のままである
- [ ] 書き出し中のコマンドは 409 であり、編集状態が変わらない
- [ ] 100 件を超えた最初の破棄だけが通知され、以後の破棄は通知しない

## フェーズ2: 回転

### 実装

- [ ] サムネイル上の回転は、そのページだけを `rotate` する
- [ ] 上部ツールバーの回転は、選択全体を 1 回の `rotate` にする
- [ ] 回転後も選択は維持する
- [ ] 回転後も、見ていた内容の付近が残るよう、大プレビューの相対位置を補正する
- [ ] 選択が 0 件のとき、ツールバーの回転は無効にし、理由をツールチップで示す

### 確認

- [ ] 右回転を 4 回すると 0 度に戻る。左回転も同様である
- [ ] 複数選択の回転が 1 件の Undo で戻る
- [ ] サムネイルの回転が、その 1 ページだけを変え、他の選択を変えない
- [ ] 書き出した PDF のページ角度が、画面の回転と一致する。元 PDF は変わらない

## フェーズ3: 削除

確認ダイアログは出さない。直後に「○ページを削除しました」と「元に戻す」を出す。「元に戻す」は Undo である。

### 実装

- [ ] サムネイル上の削除は、そのページだけを `delete` する
- [ ] 上部ツールバーの削除と、入力欄以外の Delete キーは、選択全体を 1 回の `delete` にする
- [ ] 見えているページが 0 枚になるまで削除できる。0 枚のときは書き出せない
- [ ] サムネイルで 1 枚だけ削除し、他の選択が残るときは、消していないページの選択を残す。削除したページがアクティブページでなければ、アクティブページも残す
- [ ] アクティブページ自身を消し、選択が 2 件以上残るときは、削除した位置より後ろで最も近い残りの選択を新しいアクティブページにする。後ろが無ければ直前の選択である。残る選択が 1 件ならそのページ、0 件ならアクティブページは無い
- [ ] 上部ツールバーの削除のように、選ばれていたページが残らないときは、削除位置に来たページを選択する。末尾を削除したときは前のページを選択する。1 枚も残らなければ選択は 0 件である
- [ ] Undo は、削除前の選択とアクティブページの識別子を復元する

### 確認

- [ ] ページ 2 と 5 が選択でアクティブが 5 のとき、ページ 2 を消してもページ 5 の選択とアクティブが残る
- [ ] 選択全体の削除のあと、削除位置に来たページが選択される。末尾なら前のページである
- [ ] 全ページ削除のあと、書き出しはできない。Undo でページと選択が戻る
- [ ] 元 PDF のバイト列は削除後も同じである

## フェーズ4: 並べ替え

### 実装

- [ ] 選択中のページをドラッグすると、選択全体が 1 回の `reorder` で動く
- [ ] 未選択のページをドラッグすると、既存の選択を解除してそのページだけが動く
- [ ] 動きが 8px 未満のあいだはドラッグを開始しない。クリックとして選択を変える
- [ ] 挿入位置をその場で示す。Esc でドラッグを取り消し、コマンドを送らない
- [ ] 横一列では左右の端、複数列では上下の端で、480px/秒の一定速度で自動スクロールする
- [ ] 移動後も選択を維持する
- [ ] 現在ページ番号で、指定したページの前または後へ移動できる。独自のキーボード並べ替えショートカットは置かない
- [ ] 状態が変わらない移動は通知し、履歴に入れない

### 確認

- [ ] 8px 未満の動きがクリックのままである
- [ ] 複数選択のドラッグが、見えている順を保って 1 件の Undo で戻る
- [ ] 端での自動スクロールが 480px/秒である
- [ ] 同じ位置へのドロップが履歴を増やさない

## 対象範囲と対象外

対象:

- `POST /api/session/commands` の `rotate`、`delete`、`reorder`、`undo`、`redo`
- 逆コマンドと操作前の選択を持つ履歴。上限 100 件
- サムネイルとツールバーの回転・削除、ドラッグ並べ替え、ページ番号による移動

対象外:

- 分割線の設定と解除、PDF の追加と取り除き。履歴の形は後から同じ逆コマンドを載せられるようにするが、この計画ではコマンドを実装しない
- 選択ページと分割の書き出し、未保存、「分割設定 未出力」
- 複数 PDF の末尾追加、パスワード、電子署名、設定ページ、ヘルプ、テーマ、トレイ、exe 化
- 余白、アイコン、「...」の格納順

## 合意済みの受け入れ条件

- ユーザーが 1 回行った操作を 1 単位とし、複数ページの一括操作も 1 回とする
- 実際に状態が変わった操作だけを履歴へ入れる
- Undo / Redo のあと、選択と見ている位置を可能な限り維持し、同じページを識別子で追う
- 削除、回転、並べ替えは元ページをその場で書き換えず、書き出し時に反映する
- 回転後も選択は維持する。削除のあとの選択は、仕様の「回転、削除、並べ替え」の規則に従う
- ドラッグ開始は 8px、自動スクロールは 480px/秒である

## 前提と制約

- 選択の PATCH と、読み込み直後に 1 ページ目を選択する振る舞いは、先の計画が実装している
- 成功した `POST /api/documents` は、この計画でも作業領域を 1 件で置き換える。失敗時は前の編集状態を残す。置き換え成功時だけ履歴を空にする
- 自動テストはリポジトリルートで `python -m pytest`
- 画面の確認は、回転、削除、並べ替え、Undo、Redo をブラウザで行う
