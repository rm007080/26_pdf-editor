## フェーズ1: コマンドと履歴

1 リクエストが、利用者が 1 回行った操作であり、状態が変わったときだけ Undo の 1 件になる。選択の識別子はコマンドの本文に載せない。削除、回転、並べ替えに伴う選択の変更は、サーバがセッションへ書く。

### 実装

- [ ] `POST /api/session/commands` を追加する
- [ ] トークンを要求する
- [ ] 成功時は更新後のセッションを返す
- [ ] 失敗時は編集状態も選択も履歴も変えない
- [ ] 読み込み中、ダイアログ中、書き出し中は 409 とする
- [ ] クライアントが送れる `type` は `rotate`、`delete`、`reorder`、`undo`、`redo` だけである
- [ ] それ以外の `type` は 400 とする
- [ ] `rotate` は `page_ids` と `direction`（`left` または `right`）を持つ
- [ ] 角度は 0 / 90 / 180 / 270 度で、右は +90、左は -90 である
- [ ] セッションの回転は、読み込み時 0 度からの追加回転であり、元 PDF のページが持つ回転を絶対値で置き換えない
- [ ] `delete` は `page_ids` を持つ
- [ ] 対象ページの `deleted` を真にする
- [ ] 見えている並びから外し、識別子は残す
- [ ] 元 PDF のページ実体は変えない
- [ ] `reorder` は `page_ids` と、`before_page_id` または `after_page_id` のどちらか一方だけを持つ
- [ ] 見えている並びで、指定したページの前または後へ、`page_ids` の現在順を保って動かす
- [ ] アンカーを両方言ったとき、どちらも無いとき、アンカーが `page_ids` に含まれるとき、アンカーが見えていないときは 400 とする
- [ ] `page_ids` が空、重複、未知、削除済みを含むときは 400 とする
- [ ] `direction` が `left` / `right` 以外のときは 400 とする
- [ ] 見えていないページへの `rotate` と `reorder` も 400 とする
- [ ] 見えているページの `order` は、現在ページ番号と一致する 1 から枚数までの連続整数である
- [ ] 削除と並べ替えのあと、残っている見えているページをその順で付け直す
- [ ] 削除済みページの `order` は現在ページ番号に使わない
- [ ] 画面は見えているページの `order` を現在ページ番号として出す
- [ ] `delete` の成功時、サーバが仕様の「回転、削除、並べ替え」の選択規則を適用してからセッションを返す
- [ ] クライアントは削除のあと選択を PATCH しない
- [ ] 残る選択が 0 件のとき `active_page_id` は null である
- [ ] `rotate` は選択を変えない
- [ ] 選択中のページの `reorder` は、`page_ids` が現在の選択全体と一致するときだけ受け、選択を維持する
- [ ] 一部だけの並べ替えは 400 とする
- [ ] 未選択ページのドラッグは、その 1 ページだけの `reorder` を送り、選択 PATCH は送らない
- [ ] サーバは移動後の選択をその 1 ページにし、それをアクティブページにする
- [ ] 2 ページ以上の未選択混在は 400 とする
- [ ] 履歴の 1 件は、逆コマンドと、操作前の `selected_page_ids` と `active_page_id` である
- [ ] Redo の 1 件は、元のコマンドと、操作後の選択である
- [ ] 履歴は PDF のコピーを持たない
- [ ] Undo は逆コマンドのあと、記録した操作前の選択を書く
- [ ] Redo は元コマンドのあと、記録した操作後の選択を書く
- [ ] 逆コマンドはクライアントから POST できない
- [ ] `undo` と `redo` が履歴を適用する
- [ ] 実行できない `undo` / `redo` は 400 とし、状態を変えない
- [ ] `rotate` の逆は、同じ `page_ids` で `direction` を逆にした `rotate` である
- [ ] `delete` の逆は、履歴の中だけの `restore_deleted` である
- [ ] `restore_deleted` は、削除したページを、削除前の見えている順に並べる
- [ ] `restore_deleted` の各ページは、その時点で一つ前だったページの識別子を持つ。並びの先頭だったページは null である
- [ ] `restore_deleted` を適用するときは、その順に `deleted` を偽にし、一つ前のページの直後へ入れる。null のときは先頭へ入れる
- [ ] `restore_deleted` の適用のあと、見えている `order` を 1..N に付け直す
- [ ] `reorder` の逆は、履歴の中だけの `restore_order` である
- [ ] `restore_order` は、動かしたページを、動かす前の見えている順に並べる
- [ ] `restore_order` の各ページは、その時点で一つ前だったページの識別子を持つ。並びの先頭だったページは null である
- [ ] `restore_order` を適用するときは、動かしたページをいったん見えている並びから外し、同じ順に一つ前のページの直後へ戻す。null のときは先頭へ戻す
- [ ] `restore_order` の適用のあと、見えている `order` を 1..N に付け直す
- [ ] 状態が変わらないコマンドは履歴に入れない
- [ ] 成功応答のセッションに、変わらないときは `changed: false`、変わったときは `changed: true` を載せる
- [ ] `changed` と `history_dropped` はコマンドの成功応答だけに載せ、`GET /api/session` には載せない
- [ ] Undo できる件数の上限は 100 である
- [ ] Redo の件数はこの 100 に含めない
- [ ] 超えたときは Undo 側の古いものから捨てる
- [ ] セッションは破棄を一度通知したかを覚える
- [ ] 初めて捨てた応答だけ `history_dropped: true` とし、以後の破棄は `false` である
- [ ] 置き換え読み込みで履歴を空にしたときは、この通知済みも戻す
- [ ] Undo のあとで新しい編集をしたら、Redo を捨てる
- [ ] `undo` と `redo` 自体は Redo を捨てない
- [ ] セッションに `undo_enabled`、`redo_enabled`、`undo_hint`、`redo_hint` を含める
- [ ] `GET /api/session` にも含める
- [ ] 実行できる Undo / Redo は次に起きる操作の短い文言、実行できないときは理由と、実行しても状態が変わらないことを示す
- [ ] 作業領域の置き換え読み込みが成功したときは、履歴を空にする
- [ ] 失敗した置き換えでは、前の履歴も選択も残す
- [ ] `PATCH /api/session/selection` は履歴を増やさない
- [ ] 上部ツールバーに「元に戻す」と「やり直す」を置く
- [ ] 「元に戻す」と「やり直す」が無効のときは、セッションの hint をツールチップにする
- [ ] 入力欄以外の Ctrl+Z は `undo`、Ctrl+Y は `redo` である
- [ ] 入力欄にフォーカスがあるときは、その欄の標準操作を優先する
- [ ] 画面は、`changed: false` の並べ替えを、数秒で消える通知にする
- [ ] 画面は、`history_dropped: true` を、数秒で消える通知にする
- [ ] `tests/test_session.py` に、成功を足す
- [ ] 400（未知 type、空と不正な `page_ids`、アンカーの両方と無し、見えていないページ、実行できない undo）を足す
- [ ] 409 を足す
- [ ] `changed: false` で履歴に入らない無変更を足す
- [ ] 削除後の選択（下の確認）を足す
- [ ] Undo 後の Redo 破棄を足す
- [ ] 101 件目の最初の破棄だけ `history_dropped: true` になることを足す
- [ ] 実装の中で [アーキテクチャの編集状態](../../architecture.md#編集状態) を更新する。ディスク上の追記はこの計画のレビューでは行わない。追記する要点は次のとおり。`rotate` は `page_ids` と `direction`（`left` / `right`）。`delete` は `page_ids`。`reorder` は `page_ids` と `before_page_id` または `after_page_id` の一方。`undo` と `redo` は追加の本文を持たない。逆の `restore_deleted` と `restore_order` は履歴の中だけで、クライアントが送ると 400。見えているページの現在の順は 1..N で現在ページ番号と一致し、削除と並べ替えのあと付け直す。ページの `rotation` は読み込み時 0 度からの追加回転で、元 PDF の Rotate を置き換えない。画面は、PDF が元から持つ回転にこの追加回転を足して描く。全ページ書き出しは、見えている各ページの追加回転をコピー先へ相対で足す。セッションは Undo / Redo の可否と hint を持つ。コマンド成功応答は `changed` と `history_dropped` を持つ。仕様の利用者向けの節へ、この計画から新しい要求は足さない

### 確認

- [ ] 回転の Undo が角度と選択を戻し、Redo が同じ回転と操作後の選択をやり直す
- [ ] 不正な `page_ids` は 400 であり、ページ、選択、履歴が直前のままである
- [ ] 書き出し中のコマンドは 409 であり、編集状態が変わらない
- [ ] 100 件を超えた最初の破棄だけが `history_dropped: true` になり、以後の破棄は false である
- [ ] ページ 2 と 5 が選択でアクティブが 5 のとき、ページ 2 の `delete` のあと、ページ 5 の選択とアクティブが残る
- [ ] 選択全体の `delete` のあと、削除位置に来たページが選択される
- [ ] 選択全体の `delete` で末尾を消したときは、前のページが選択される
- [ ] 全削除では選択 0 件、`active_page_id` は null である
- [ ] 未選択 1 ページの `reorder` のあと、そのページだけが選択される
- [ ] 未選択 1 ページの `reorder` の Undo で、操作前の選択に戻る

## フェーズ2: 回転

### 実装

- [ ] サムネイル上の回転は、そのページだけを `rotate` する
- [ ] サムネイル上の回転は、他の選択を変えない
- [ ] 上部ツールバーの回転は、選択全体を 1 回の `rotate` にする
- [ ] 回転後も選択は維持する
- [ ] サムネイルに、PDF が元から持つ回転へセッションの追加回転を足して描く
- [ ] 大プレビューに、PDF が元から持つ回転へセッションの追加回転を足して描く
- [ ] 選択計画がサムネイル用描画と、大プレビューのズーム、パン、3 枚キャッシュを別関数にしているときは、その両方の実描画へ追加回転を渡す
- [ ] `paintFittedPage` が残っている経路があれば、そこにも同じ追加回転を渡す
- [ ] サムネイルだけ、または大プレビューだけに回転が乗る状態にはしない
- [ ] 回転後も、見ていた内容の付近が残るよう、大プレビューの相対位置を補正する
- [ ] 書き出しは、見えている各ページの追加回転を、コピー先のページへ相対で足す
- [ ] `app/export.py` の `_plan` から、各ページの追加回転を `Job` を経て `_copy_pages` まで運ぶ。今は `source_page` だけを `Job` に渡している
- [ ] 元 PDF のバイト列は変えない
- [ ] `tests/test_export.py` に、右回転したページの書き出し角度が画面と同じ追加回転であることを足す
- [ ] 選択が 0 件のとき、ツールバーの回転は無効にする
- [ ] その無効の理由をツールチップで示す

### 確認

- [ ] 右回転を 4 回すると 0 度に戻る
- [ ] 左回転を 4 回すると 0 度に戻る
- [ ] 複数選択の回転が 1 件の Undo で戻る
- [ ] サムネイルの回転が、その 1 ページだけを変え、他の選択を変えない
- [ ] 書き出した PDF のページ角度が、画面の回転と一致する
- [ ] 元 PDF は変わらない

## フェーズ3: 削除

### 実装

- [ ] 確認ダイアログは出さない
- [ ] 直後に「○ページを削除しました」と「元に戻す」を出す
- [ ] 「元に戻す」は、ツールバーと同じ `undo` である
- [ ] サムネイル上の削除は、そのページだけを `delete` する
- [ ] 上部ツールバーの削除は、選択全体を 1 回の `delete` にする
- [ ] 入力欄以外の Delete キーは、選択全体を 1 回の `delete` にする
- [ ] 見えているページが 0 枚になるまで削除できる
- [ ] 0 枚のときは書き出せない
- [ ] 選択が 0 件のとき、ツールバーの削除は無効にする
- [ ] その無効の理由をツールチップで示す
- [ ] 選択が 0 件のとき、Delete キーはコマンドを送らない
- [ ] サムネイルで 1 枚だけ削除し、他の選択が残るときは、消していないページの選択を残す
- [ ] 削除したページがアクティブページでなければ、アクティブページも残す
- [ ] サムネイルで 1 枚だけ削除したあとの選択は、フェーズ1のサーバ規則の結果であり、画面は PATCH で上書きしない
- [ ] アクティブページ自身を消し、選択が 2 件以上残るときは、削除した位置より後ろで最も近い残りの選択を新しいアクティブページにする
- [ ] そのとき後ろが無ければ、直前の選択を新しいアクティブページにする
- [ ] アクティブページ自身を消したとき、残る選択が 1 件ならそのページ、0 件ならアクティブページは無い
- [ ] 上部ツールバーの削除のように、選ばれていたページが残らないときは、削除位置に来たページを選択する
- [ ] 選ばれていたページが残らず、末尾を削除したときは、前のページを選択する
- [ ] 選ばれていたページが残らず、1 枚も残らなければ、選択は 0 件である
- [ ] Undo は、削除前の選択とアクティブページの識別子を復元する

### 確認

- [ ] ページ 2 と 5 が選択でアクティブが 5 のとき、ページ 2 を消してもページ 5 の選択とアクティブが残る
- [ ] 選択全体の削除のあと、削除位置に来たページが選択される
- [ ] 選択全体の削除で末尾を消したときは、前のページが選択される
- [ ] 全ページ削除のあと、書き出しはできない
- [ ] Undo でページと選択が戻る
- [ ] 元 PDF のバイト列は削除後も同じである

## フェーズ4: 並べ替え

### 実装

- [ ] 選択中のページをドラッグすると、選択全体が 1 回の `reorder` で動く
- [ ] ドラッグの前後に選択 PATCH は送らない
- [ ] 未選択のページをドラッグすると、既存の選択を解除してそのページだけが動く
- [ ] 未選択ページのドラッグで送るのは、その 1 ページの `reorder` だけである
- [ ] 動きが 8px 未満のあいだはドラッグを開始しない
- [ ] その動きはクリックとして選択を変える
- [ ] 挿入位置をその場で示す
- [ ] Esc でドラッグを取り消し、コマンドを送らない
- [ ] 横一列では左右の端、複数列では上下の端で、480px/秒の一定速度で自動スクロールする
- [ ] 移動後も、選択中だったページのドラッグでは選択を維持する
- [ ] 現在ページ番号で、指定したページの前または後へ移動できる
- [ ] 独自のキーボード並べ替えショートカットは置かない
- [ ] 状態が変わらない移動は通知する
- [ ] 状態が変わらない移動は履歴に入れない
- [ ] 状態が変わらない移動の応答は `changed: false` である

### 確認

- [ ] 8px 未満の動きがクリックのままである
- [ ] 複数選択のドラッグが、見えている順を保って 1 件の Undo で戻る
- [ ] 戻った並びは、ドラッグ前の現在ページ番号と一致する
- [ ] 端での自動スクロールが 480px/秒である
- [ ] 同じ位置へのドロップが履歴を増やさない

## 対象範囲と対象外

対象:

- `POST /api/session/commands` の `rotate`、`delete`、`reorder`、`undo`、`redo`
- 逆コマンドと操作前の選択を持つ履歴。Undo できる件数の上限 100
- サムネイルとツールバーの回転・削除、ドラッグ並べ替え、ページ番号による移動
- 追加回転の画面描画と、全ページ書き出しへの反映
- ツールバーの元に戻す / やり直す、Ctrl+Z / Ctrl+Y、削除直後の「元に戻す」

対象外:

- 分割線の設定と解除、PDF の追加と取り除き。この計画の削除と並べ替えは分割線の状態を持たない。分割線の位置更新は、分割線を実装する計画が行う。履歴の形は後から同じ逆コマンドを載せられるようにするが、この計画ではそのコマンドを実装しない
- 選択ページと分割の書き出し、未保存、「分割設定 未出力」
- 複数 PDF の末尾追加、パスワード、電子署名、設定ページ、ヘルプ、テーマ、トレイ、exe 化
- 余白、アイコン、「...」の格納順

## 合意済みの受け入れ条件

- ユーザーが 1 回行った操作を 1 単位とし、複数ページの一括操作も 1 回とする
- 実際に状態が変わった操作だけを履歴へ入れる
- Undo / Redo のあと、選択と見ている位置を可能な限り維持し、同じページを識別子で追う
- 削除、回転、並べ替えは元ページをその場で書き換えず、書き出し時に反映する
- 回転後も選択は維持する。削除のあとの選択は、仕様の「回転、削除、並べ替え」の規則に従う
- ドラッグ開始は 8px、自動スクロールは 480px/秒である

## 前提と制約

- 選択の PATCH と、読み込み直後に 1 ページ目を選択する振る舞いは、先の計画が実装している
- 成功した `POST /api/documents` は、この計画でも作業領域を 1 件で置き換える。失敗時は前の編集状態を残す。置き換え成功時だけ履歴を空にする
- 自動テストの境界は、この API とセッションの中身である。内部ファイルの分割は、この境界を守る範囲で実装が決める
- 自動テストはリポジトリルートで `python -m pytest`
- 画面の確認は、回転、削除、並べ替え、Undo、Redo をブラウザで行う
