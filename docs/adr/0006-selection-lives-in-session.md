# 選択はセッション上のページ識別子として持つ

選択とアクティブページは、ページの項目（順番、削除、回転）とは別である。バックエンドのセッションが、見えているページの識別子の集合と、アクティブページの識別子を持つ。Undo の履歴もバックエンドにあるので、操作を戻したあとと F5 のあとで、同じページを選び直せる。

## 検討した選択肢

- 画面だけが選択を持つ。ページの正本はバックエンドのままになる。戻したあとの選択が履歴とずれ、F5 では選択が消えるので不採用。
- セッションが識別子の集合として持つ。採用。

## 結果

- 選択は、各ページの削除状態や回転には入れない。
- コマンドの成功時に返すセッションに、選択とアクティブページを含める。
- 選択が 0 件のときは、アクティブページは無い。
- 選択の更新は `PATCH /api/session/selection` で送る。`POST /api/session/commands` には載せない。選択の変更だけでは Undo の履歴は増えない。
