# 編集操作は1つのコマンド API にする

回転、削除、並べ替えと、後から足す分割線や PDF の追加は、利用者が1回行った操作を1リクエストで送る。その1回が Undo の1件になる。編集状態の正本はバックエンドのままである。

## 検討した選択肢

- 操作ごとの URL。テストは分かれやすい。Undo の1件と URL がずれ、操作が増えるたびに口が増えるので不採用。
- 画面がページの並び全体を PUT する。差分から「1回の操作」を復元することになり、仕様の操作単位とずれるので不採用。
- `POST /api/session/commands` の1本。採用。

## 結果

- 成功時は更新後のセッションを返す。失敗時は編集状態を変えない。
- 状態が変わらない操作は履歴に入れない。
- 画面はページの順番、削除、回転の正本を持たない。
- 選択の更新はコマンドにしない。クリックのたびに Undo の1件にはしない。
