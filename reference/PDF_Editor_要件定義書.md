# PDF Editor 要件定義書

**作成日:** 2026-09-25\
**対象:** Windows向けローカルPDF編集Webアプリ\
**状態:** 要件定義完了（技術設計前）

## 1. 目的・スコープ

PDFのページ構成を安全かつ直感的に編集する。主機能は、結合、分割、並べ替え、削除、左右90°回転、選択ページ書き出し、サムネイル／大プレビューである。

対象外:
PDF本文への文字・図形・マーカー追加、OCR、トリミング、印刷、画像/Word/Excel変換、ページサイズ統一、ページ複製、逆順、しおり・メタデータ編集。

## 2. 基本原則

-   元PDFは一切変更しない。完成物は新しいPDFとして保存する。
-   削除・回転・並べ替えは元ページを物理変更せず、軽量な編集状態として管理する。
-   PDF編集はオフラインで完結し、PDF本文、サムネイル、ファイル名、パスワード、編集内容を外部送信しない。
-   失敗・キャンセル時に不完全なPDFを完成品として残さない。
-   数百ページ・大容量PDFを想定し、全PDFをむやみにRAMへ展開しない。
-   未保存判定は「操作したか」ではなく「現在の出力状態」で判断する。

## 3. アプリ構成・起動

-   Web UI + Pythonバックエンドを基本構成とする。
-   Windowsローカルアプリとして起動し、ローカルWebサーバーと既定ブラウザを使用する。
-   localhost / 127.0.0.1 のみに限定し、他PCからアクセス不可。
-   正式対応: Microsoft Edge / Google
    Chrome。その他は警告するが利用禁止にはしない。
-   PC専用。スマホ・タブレット対象外。
-   Windows表示倍率100/125/150%等、ノートPC～ワイドモニターへ対応。
-   原則1インスタンス・1編集タブ。再起動時は既存バックエンドへ接続。
-   タブを閉じてもバックエンドは即終了しない。
-   システムトレイに「開く」「終了」を用意。Windowsログイン時の自動起動なし。
-   アプリ内「終了」で一時データを清掃しバックエンドを終了する。

## 4. PDF入力

-   入力形式はPDFのみ。
-   ファイル選択とドラッグ＆ドロップに対応。複数PDFを一度に読み込める。
-   複数PDFは選択・ドロップ順で1つの作業領域へページ単位で展開。単一PDFならそのPDFだけを編集。
-   読み込み完了後は1ページ目を自動選択。
-   編集途中でもPDF追加可能。追加先は末尾。追加後も現在の選択・プレビューを維持。
-   読み込み中は新規追加を無効化。キャンセル時はその追加全体を取り消す。
-   読み込み成功後、Windows
    Temp配下の専用領域へセッション用コピーを作成。以後はコピーを使用し元PDFをロックしない。
-   元PDFが移動・削除・外部変更されてもセッション継続可能。
-   一時コピー等は「新しく始める」・正常終了時に削除。異常終了の残骸は次回起動時に清掃。
-   内容ハッシュで重複判定。重複時は確認し了承時のみ追加。
-   同一PDFの複数追加は追加単位で独立管理し、元データの一時コピーは共有。ハッシュはセッション中のみ保持。

## 5. パスワード・署名

-   開くためのパスワード付きPDFに対応。PDFごとに順番に入力。
-   試行回数制限なし。通常は伏字、目アイコンで一時表示。
-   パスワードはログ・設定へ保存しない。
-   入力キャンセルしたPDFだけ除外し、他PDFは継続。
-   書き出しPDFへの新規パスワード設定は対象外。
-   電子署名PDFは、編集後に署名が有効でなくなる可能性を警告し、了承後に編集する。

## 6. ページ状態モデル

各ページに非表示の一意IDを持たせ、元PDF追加単位、元ページ番号、現在順、削除状態、回転状態(0/90/180/270°)を管理する。

-   削除: ページ本体は残し「削除済み」状態にする。
-   回転: 角度だけを保持する。
-   並べ替え: ページIDの並び順だけを変更する。
-   実PDFへの反映は書き出し時に行う。

## 7. 選択・編集

-   単一選択、Ctrl+クリック、Shift+クリック、すべて選択。
-   Ctrl+Aはサムネイル一覧フォーカス時のみ全ページ選択。
-   Shift+矢印で連続範囲を拡張・縮小。
-   選択中は枠/背景 + チェックマーク。
-   余白クリックまたは通常状態のEscで選択解除。
-   選択0件ではプレビューを空にし「ページを選択してください」。
-   回転は左90°/右90°。複数一括対応。回転後も選択維持。
-   削除は単一/複数対応。毎回の確認なし。直後に「○ページを削除しました
    \[元に戻す\]」。
-   0ページまで削除可能。0ページ時は書き出し不可。
-   削除後は削除位置に来たページ、末尾なら前ページを選択。

## 8. 並べ替え

-   1ページまたは選択中の複数ページをドラッグ＆ドロップ。
-   選択中ページをドラッグすると選択全体を移動。未選択ページなら既存選択を解除してそのページだけ移動。
-   挿入位置をリアルタイム表示。移動後も選択維持。
-   Escでドラッグキャンセル。一定距離以上の移動でドラッグ開始。
-   横一列では左右端、複数列では上下端で一定速度の自動スクロール。
-   大量ページ向けに「指定ページの前/後へ移動」を提供。現在ページ番号を使う。
-   状態が変わらない移動は通知し、Undo履歴へ追加しない。

## 9. サムネイル・プレビュー

-   サムネイルは「横一列+横スクロール」と「複数列+縦スクロール」を切替可能。前回方式を記憶。
-   サイズは小/中/大。前回設定を記憶。切替後もアクティブページが見える位置へ調整。
-   低～中解像度で軽量生成。横一列では通常ホイールで左右スクロール。
-   各サムネイルに左回転・右回転・削除。右クリックメニューなし。ダブルクリック特別動作なし。
-   現在ページ番号を目立たせ、元PDF名+元ページ番号を補助表示。長い名前は省略しホバーで全文。フルパスは通常非表示。
-   大プレビューは編集画面内に常設。複数選択時もアクティブページ1枚のみ表示。
-   表示モード: ページ全体 / 幅に合わせる / 100%。初期はページ全体。
-   +/- と
    Ctrl+ホイールでズーム。25%程度の段階式。最大400%程度を目安にテストで確定。
-   拡大時はスクロールバー + マウスドラッグのパン。
-   前へ/次へ、←/→でページ移動。移動時は複数選択解除し移動先1ページを選択。
-   ページ切替時も倍率・表示モード・ページ内相対位置を可能な限り維持。回転時も見ていた内容付近が残るよう補正。
-   全画面プレビューなし。ズーム状態は次回起動へ持ち越さない。

## 10. 分割・書き出し

-   ページ間へ分割線を設定/解除。分割線は特定ページではなく現在の「位置」に紐づける。
-   ページ移動・削除後も可能な限り同位置を維持し、0ページPDFを生む線は自動除去。
-   分割線操作はUndo/Redo対象。「すべての分割線を解除」も1操作として扱う。
-   書き出しは①全ページを1つのPDF、②分割、③選択ページの3種類。全ページを主ボタン、他2つを隣接メニューとする。
-   選択ページはクリック順ではなく現在の文書順で出力。未選択時は無効化。
-   分割は連番ファイル名を自動提案し個別変更可能。保存先フォルダは1回指定。
-   単一元PDFなら `元ファイル名_編集済み.pdf` を初期候補とする。
-   前回保存先を記憶。アクセス不可なら標準場所へフォールバックして通知。
-   同名ファイルは上書きせず `(1)`, `(2)` 等を自動付与。
-   書き出し前に空き容量確認。
-   最終名へ直接書かず一時ファイルへ生成し、完成後に「PDFとして開ける」「予定ページ数と一致」を検証して最終化。
-   失敗/キャンセル時は不完全ファイルを可能な限り削除し編集状態を保持。
-   書き出し中は編集をロック。進捗率、処理ページ数、処理段階を表示。残り時間予測は不要。
-   保存成功後も編集状態を残し、ファイル名・保存先と「PDFを開く」「保存先を開く」を表示。

## 11. ネットワーク共有

-   Windowsから通常アクセスできる共有上のPDFを読み込み・保存可能。
-   読み込み後はローカル一時コピーを使用。
-   コピー途中の切断は失敗扱い。不完全コピーを削除し自動再開しない。
-   共有保存も一時ファイル→検証→最終リネーム。切断・リネーム失敗時は保存失敗とし自動再送しない。
-   ネットワーク共有のフルパスはエラーログへ記録しない。

## 12. Undo / Redo

-   削除、回転、並べ替え、PDF追加/取り除き、分割線等を対象。
-   「ユーザーが1回実行した操作 = 1単位」。複数ページ一括操作も1回。
-   PDF本体コピーではなく逆操作に必要な軽量状態を保持。
-   起動中は原則すべてUndo可能。ただし異常な履歴増大に備え十分大きな安全上限を内部設定し、超過時は古い履歴から破棄する。
-   初回破棄時だけ通知。Undo後に新編集したらRedo履歴を破棄。
-   実際に状態変化した操作だけ履歴へ記録。
-   Undo/Redo後も現在の選択・閲覧位置を可能な限り維持し、内部IDで同じページを追跡。
-   実行不能なUndo/Redoは無効表示し、ホバー/フォーカスで理由や次の操作内容を表示。
-   履歴一覧から任意時点へジャンプする機能は設けない。書き出し後も履歴を維持。

## 13. 未保存・未出力状態

-   単一PDFを読み込んだだけなら原本状態を「保存済み相当」の基準とする。
-   複数PDFの初回読み込み、PDF追加、回転、削除、並べ替え等で現在状態が基準と異なれば未保存。
-   Undo等で基準状態と完全一致すれば未保存を自動解除。
-   判定は内部ID・順番・回転状態等の軽量状態で行う。
-   全ページPDFの正常書き出し時だけ、その状態を新しい保存基準にする。
-   選択ページ/分割書き出しでは通常の「未保存」を解除しない。
-   分割線は通常の未保存判定には含めず、別に「分割設定 未出力」を管理。
-   分割結果へ影響する編集後は再び未出力。
-   画面には必要時だけ「未保存」「分割設定
    未出力」を表示し、クリックで対応する通常の書き出しフローへ誘導。
-   終了/「新しく始める」時、失われる状態が複数あれば1つの確認画面にまとめる。何も失わなければ確認なし。

## 14. UI・キーボード

-   上部共通ツールバー + サムネイル上の主要操作ボタン。
-   画面幅が十分ならアイコン+文字、狭い場合はアイコン中心。低優先操作は固定優先順位で「...」へ格納。
-   削除・破棄・終了等は警告色/アイコンで区別。
-   無効ボタンは理由と利用条件をツールチップ表示。
-   プレビュー領域とサムネイル領域の境界をドラッグして高さ調整可能。最低高さを設け、前回比率を記憶。
-   状態表示: 総ページ数、選択ページ数、元PDF数。
-   ページ番号ジャンプを提供。範囲外はエラー。Enterでも実行し、成功後は入力欄を空にする。
-   Tabで主要要素へ移動可能。フォーカスを明確に表示。
-   サムネイル一覧では←/→、複数列では↑/↓でも移動。Shift+矢印で連続選択。
-   Delete、Ctrl+A、Ctrl+Z/Y、←/→は入力欄等の標準操作を壊さないようフォーカスに応じて動作を切り替える。
-   独自のキーボード並べ替えショートカットは設けない。

## 15. 設定・ヘルプ

-   ライト/ダークテーマ切替。前回設定を記憶。
-   設定は独立ページ。変更は即時反映・自動保存。
-   上部ナビゲーションに「PDF編集」「設定」「ヘルプ」。ブラウザ戻る/進むにも対応。
-   設定/ヘルプから戻っても選択、倍率、スクロール位置等を可能な限り維持。
-   ヘルプは基本操作、複数選択、分割、ショートカットを文章+簡単な図解で説明。検索機能なし。
-   設定下部にアプリ名、バージョン、「更新を確認」を表示。
-   設定はWindowsユーザーごとに保存。
-   前回の読み込み/保存フォルダは記憶するが、最近使ったPDF名/パスの履歴は残さない。
-   サムネイルサイズ、表示方式、領域比率を記憶。ズーム倍率・ページ表示位置は次回へ持ち越さない。
-   「設定を初期状態に戻す」は確認後に実行。

## 16. 自動終了・バックグラウンド

-   ブラウザ接続/操作がない状態が一定時間続けば自動終了し一時データを削除。
-   初期値2時間。設定で30分/1時間/2時間/4時間から選択。
-   終了前に警告し「作業を続ける」でタイマーをリセット。
-   クリック、キー操作、スクロール、設定操作等を実質的な操作とし、単なるマウス移動は対象外。
-   ブラウザクラッシュだけならバックエンドが生きている限り再接続して状態復元。F5でも可能な限り復元。
-   Pythonバックエンド自体が異常終了した場合は編集状態を復元せず、次回起動時に一時データを清掃して案内。
-   Windowsシャットダウン/再起動は妨げない。スリープはOS設定に任せ、継続不能なら通常の処理失敗として扱う。

## 17. 通知・エラー・ログ

-   通常の成功通知は数秒で自動消去。エラー/重要警告はユーザーが閉じるまで残す。
-   複数PDF読み込みでは失敗したPDFだけをファイル名・理由とともに通知。全成功時は簡潔な成功通知。
-   開発版は詳細エラーを表示。完成版は利用者向けの分かりやすいメッセージだけ表示。
-   完成版はPDF本文、パスワード、ファイル名、フルパス、共有サーバー名等を含めない技術ログをローカル保存。
-   ログは保存期間と総容量の両方に上限を設け古いものから削除。
-   設定画面に「エラーログの保存先を開く」を用意。
-   バックグラウンド処理完了/失敗時はWindows通知。機密情報は通知に出さない。
-   Windows通知は設定でON/OFF可能。初期値ON。

## 18. セキュリティ・更新

-   localhost限定に加え、起動ごとの一時的な認証情報等で正規Web
    UIからのAPI要求だけを受け付ける方向とする。
-   認証情報はユーザー入力不要、終了時に破棄。
-   開発者向けAPIドキュメントは開発版のみ有効、完成版では無効。
-   PDF関連データは外部通信しない。
-   更新確認はユーザーが「更新を確認」を押した場合だけ。確認先は配布設計時に決定。
-   更新は最新版の有無を通知するところまでとし、自動ダウンロード/自動インストールは行わない。

## 19. PDF品質・互換性

-   可能な処理では元PDFページを画像化せずPDFページとして扱う。
-   勝手な再圧縮を行わず、文字・ベクター・画像品質を可能な限り維持。
-   元ページサイズを維持。
-   メタデータは積極的に引き継がない。しおりは引き継がない。
-   PDF内のWebリンク/内部リンクの維持は保証しない。
-   一部ページ自体が破損して正常処理できないPDFは、そのPDF全体を追加しない。
-   複数PDF中の1ファイルが失敗しても正常な他PDFは読み込む。

## 20. 非機能要件

### 性能

-   数百ページ、将来的には500ページ級を想定。
-   必要部分を必要時に読み込み、プレビューキャッシュは上限付きとする。
-   PC全体のメモリ監視機能は設けず、アプリ自身のメモリ消費を抑える。

### 信頼性

-   書き出しは一時ファイル→検証→最終化。
-   キャンセル/異常時は中間データを清掃。
-   原本は常に保護する。

### 保守性

-   開発版/完成版のエラー表示を分離。
-   バージョン番号を確認可能。
-   技術ログを機密情報なしで保持。

### ユーザビリティ

-   日本語UIのみ。
-   操作不能な理由をUI上で説明。
-   確認ダイアログは、未保存破棄、設定初期化、重複PDF、大容量PDF、電子署名等、意味のある場面に限定。
-   主要操作はマウスと一般的なキーボード操作の両方に対応。

## 21. 現時点の未決事項（技術設計・性能テストで決定）

以下は要件上の致命的不明点ではなく、実装・検証段階で決定する。

-   Python Webフレームワークの最終選定（FastAPI等）
-   フロントエンド技術（素のHTML/CSS/JavaScript、React等）
-   PDF処理ライブラリの最終選定
-   exe化/ランチャー/システムトレイ実装方式
-   Windowsの保存ダイアログ・保存先を開く・PDFを開く等のWeb
    UIとローカルOS連携方式
-   サムネイル具体解像度
-   高解像度プレビューキャッシュ数
-   Undo履歴の安全上限値
-   大容量警告のファイルサイズ/ページ数しきい値
-   最大ズーム倍率、ズーム刻みの最終値
-   ドラッグ開始距離、自動スクロール速度
-   ログ保存期間・最大容量
-   更新確認先
-   UIの具体的なpx値、余白、アイコン、フォントサイズ等

## 22. 次工程

本要件定義を基準として、次は以下の順で技術設計へ進む。

1.  技術スタック選定
2.  全体アーキテクチャ設計
3.  編集状態・Undo/Redoデータモデル設計
4.  PDF処理ライブラリ選定と技術検証
5.  画面構成・UI設計
6.  ローカルWebサーバー、exeランチャー、システムトレイ設計
7.  セキュリティ・一時ファイル・ログ設計
8.  大容量PDFの性能検証
9.  MVP実装
10. Edge/Chrome、画面倍率、ネットワーク共有を含む受入テスト

### 要件定義上の結論

現時点で、実装開始を妨げる致命的な要件不明点は残っていない。以降の細かな数値やライブラリ選定は、要件追加ではなく技術設計・性能テストの領域として扱う。
